# 前端字段配置

## 模块定位

为请求扩展字段（`request_ext`）提供前端 GUI 配置入口。部署方/最终用户在对话界面通过设置浮窗维护 `user_id` / `group_id` 以及若干自定义键值对；保存后字段随 WebSocket 连接 URL query 发送给后端，由 `jiuwenclaw.request_ext` 抽取并贯穿到 Agent rail。

与 [扩展字段透传](./扩展字段透传.md) 配套使用：前端负责输入与传递，后端负责接收与暴露。

## 入口位置

聊天界面输入框下方工具条，从左到右顺序：

```
[滑块图标 ⚙ ← 本控件]  [新建会话 +]  [按住说话 🎤]  [模型选择]  [发送 →]
```

点击滑块图标弹出"请求扩展字段"浮窗，编辑完点击"保存并应用"即生效。

## 浮窗结构

```
┌──────────────────────────────────────┐
│  请求扩展字段                      ✕  │
│  用户身份与自定义字段，将随每次          │
│  会话连接透传给后端                    │
├──────────────────────────────────────┤
│  User ID                              │
│  [_________________________]           │
│                                       │
│  Group ID                              │
│  [_________________________]           │
│                                       │
│  ── 自定义键值对 ───────────         │
│  Key                Value             │
│  [Authorization▼] [___________]  🗑   │
│  [X-Tenant-Id  ▼] [___________]  🗑   │
│  [+ 添加]                              │
├──────────────────────────────────────┤
│  保存后将自动重连以应用     [取消] [保存]│
└──────────────────────────────────────┘
```

| 字段 | 必填 | 说明 |
|---|---|---|
| User ID | 否 | 留空则不透传 `user_id` |
| Group ID | 否 | 留空则不透传 `group_id` |
| 自定义键值对 | 否 | Key 从白名单选择；同一 key 可多行（不推荐） |

### Key 白名单

自定义 key 名固定在以下集合，避免任意客户端传任意字段：

* `Authorization`
* `X-Tenant-Id`
* `X-Trace-Id`
* `X-Locale`

如需扩展，修改 `jiuwenclaw/web_enterprise/src/stores/extSettingsStore.ts` 中的 `EXT_CUSTOM_KEY_WHITELIST` 常量，同时确保后端 `JIUWENCLAW_REQUEST_EXT_FORWARD_HEADERS` 包含对应字段名。

## 前端实现

### 关键文件

| 文件 | 角色 |
|---|---|
| `web_enterprise/src/stores/extSettingsStore.ts` | zustand store + `localStorage` 持久化；`saveAndApply()` 触发 WS 重连事件 |
| `web_enterprise/src/components/ExtSettingsModal/index.tsx` | 滑块图标按钮 + 设置浮窗（自包含的 `ExtSettingsControl` 组件） |
| `web_enterprise/src/components/ChatPanel/InputArea.tsx` | 工具条上挂载 `<ExtSettingsControl />` |
| `web_enterprise/src/types/websocket.ts` | `WebConnectOptions` 新增 `userId / groupId / extraFields` |
| `web_enterprise/src/services/webClient.ts` | `buildWsUrl` 把新字段拼到 WS query |
| `web_enterprise/src/hooks/useWebSocket.ts` | 首次连接与重连事件均从 store 拉最新设置 |
| `web_enterprise/src/i18n/locales/zh.json`, `en.json` | 中英文文案 |

### 数据流

```
[设置浮窗编辑后点击「保存并应用」]
        │
        ▼
extSettingsStore.saveAndApply(snapshot)
        │── saveToStorage(snapshot)                ← 持久化到 localStorage
        │── set(snapshot)                          ← 更新 zustand state
        └── window.dispatchEvent(                  ← 触发 WS 重连事件
                'jiuwenclaw:ws-reconnect-request')
        │
        ▼
useWebSocket: WS_RECONNECT_EVENT listener
        │── useExtSettingsStore.getState()         ← 拉最新快照
        │── extSettingsToQueryFields(snapshot)     ← 拍平成 query map
        │── webClient.disconnect(reason).then(
        │       webClient.connect(connectOptions))
        │
        ▼
webClient.buildWsUrl(options)
        │── URLSearchParams 累加 user_id / group_id / 自定义 key
        │
        ▼
ws://host:19000/ws?user_id=alice&group_id=g1&Authorization=Bearer+xxx
        │
        ▼  (后端链路见 docs/zh/扩展字段透传.md)
```

### 重连反馈

保存后复用项目已有的连接状态指示灯（`StatusBar` 中已有的 `isConnected` 状态变化），不引入额外 toast。重连过程通常 1-2 秒；过程中如发送消息会沿用 `useWebSocket` 现有的重连排队逻辑。

### 持久化语义

`localStorage` key：`jiuwenclaw_ext_settings`

存储结构：

```json
{
  "userId": "alice",
  "groupId": "g1",
  "customKVs": [
    {"key": "Authorization", "value": "Bearer xxx"},
    {"key": "X-Tenant-Id", "value": "acme"}
  ]
}
```

浏览器刷新后状态自动恢复；用户可手动清空 localStorage 解除。

## 端到端测试

完整链路：

```
前端浮窗 → ws query → web_channel → request_ext → ContextVar → rail get_ext()
```

### 测试 rail 安装

为验证后端能读取到字段，在 RailManager 扩展目录放一个测试 rail：

**路径**：`<USER_WORKSPACE>/agent/jiuwenclaw_workspace/extensions/test_passthrough/rail.py`

其中 `<USER_WORKSPACE>` 由 `get_multi_tenant_user_workspace_dir("default", "default")` 返回，单机部署下通常为 `~/.jiuwenclaw/service_default/agent_default`。

```python
from __future__ import annotations
import logging
from openjiuwen.core.single_agent.rail.base import AgentCallbackContext
from openjiuwen.harness.rails.base import DeepAgentRail
from jiuwenclaw.request_ext import get_ext

logger = logging.getLogger("test_passthrough_rail")


def _format(ext: dict) -> str:
    masked = {}
    for k, v in ext.items():
        if k.lower() in ("authorization", "x-trace-id") and isinstance(v, str) and len(v) > 12:
            masked[k] = f"{v[:8]}***{v[-4:]}"
        else:
            masked[k] = v
    return repr(masked)


class CustomRail(DeepAgentRail):
    priority = 1

    async def before_invoke(self, ctx: AgentCallbackContext) -> None:
        ext = get_ext()
        if ext:
            logger.warning(
                "[TestPassthroughRail] before_invoke ext=%s "
                "user_id=%r group_id=%r authorization_present=%s",
                _format(ext), ext.get("user_id"), ext.get("group_id"),
                "Authorization" in ext,
            )
        else:
            logger.warning("[TestPassthroughRail] before_invoke ext is EMPTY")

    async def before_tool_call(self, ctx: AgentCallbackContext) -> None:
        ext = get_ext()
        tool_name = getattr(getattr(ctx, "inputs", None), "tool_name", "?")
        logger.warning(
            "[TestPassthroughRail] before_tool_call tool=%s ext=%s",
            tool_name, _format(ext) if ext else "EMPTY",
        )
```

**配置**：同目录下 `extensions_config.json` 注册启用：

```json
{
  "test_passthrough": {
    "name": "test_passthrough",
    "class_name": "CustomRail",
    "enabled": true,
    "description": "E2E test rail for request_ext propagation",
    "priority": 1
  }
}
```

### 步骤

**Step 1：设置后端环境变量并重启 backend**

```bash
pkill -f "jiuwenclaw.app_agentserver"
pkill -f "jiuwenclaw.app_gateway"
sleep 2

# 进入 jiuwenclaw 源码目录
export JIUWENCLAW_REQUEST_EXT_FORWARD_HEADERS="user_id,group_id,Authorization,X-Tenant-Id,X-Trace-Id,X-Locale"
PYTHONUNBUFFERED=1 uv run jiuwenclaw-app
```

注：rail 由 `RailManager` 在 Agent 首次实例化时按需加载（一般为收到首条 chat 消息时），并非启动期立即加载。

**Step 2：确保前端 dev server 在跑**

```bash
cd jiuwenclaw/web_enterprise
npm run dev    # 默认起在 http://localhost:5173
```

**Step 3：浏览器操作**

1. 打开 `http://localhost:5173`
2. 等待对话界面加载完，工具条上的滑块图标可见
3. 点击滑块图标 → 弹出设置浮窗
4. 填入：
   - User ID: `alice`
   - Group ID: `g1`
   - 添加一行：[Authorization] [Bearer test-token-xxx]
   - 添加一行：[X-Tenant-Id] [acme]
5. 点击「保存并应用」→ 浮窗关闭 + 连接灯闪烁
6. 在对话框发送任意消息（例如 `你好`）

**Step 4：观察后端日志**

`jiuwenclaw-app` 的 stdout 中应看到（关键字 `[TestPassthroughRail]`）：

```
[TestPassthroughRail] before_invoke ext={'user_id': 'alice', 'group_id': 'g1', 'Authorization': 'Bearer t***-xxx', 'X-Tenant-Id': 'acme'} user_id='alice' group_id='g1' authorization_present=True
```

如果 agent 调用了任何工具，还应见：

```
[TestPassthroughRail] before_tool_call tool=<tool_name> ext={...}
```

值长度大于 12 时按首 8 + 末 4 掩码（`_format` 实现）；短值会直接显示明文。

### 验证 checklist

| 验证项 | 期望 |
|---|---|
| 浏览器开发者工具 Network → WS 连接 URL | 含 `?user_id=alice&group_id=g1&Authorization=Bearer+xxx&X-Tenant-Id=acme` |
| backend 日志 `[TestPassthroughRail] before_invoke` | `ext` 字典内容与前端输入一致；长 Authorization 已按首 8 + 末 4 掩码 |
| 删除某行 KV 重新保存 | 重连后新 query 不再含该字段，日志中也不见 |
| 全部清空保存 | `before_invoke ext is EMPTY` 日志触发 |
| 浏览器刷新页面 | 字段从 `localStorage` 自动恢复，连接 URL 仍带这些字段 |
| User ID / Group ID 留空 | query 中不含 `user_id` / `group_id`；日志中对应字段为 `None` |

## 总结

| 维度 | 现状 |
|---|---|
| **后端改动** | 0 行（完全复用既有 `request_ext` 模块与 `web_channel` 入口） |
| **前端新增组件** | 1 个 store + 1 个 Modal + 滑块按钮 |
| **前端修改文件** | InputArea / webClient / useWebSocket / WebConnectOptions / i18n 共 6 处 |
| **配置项** | 仅依赖环境变量 `JIUWENCLAW_REQUEST_EXT_FORWARD_HEADERS` |
| **安全约束** | 自定义 key 受前端白名单 + 后端 forward_headers 双重过滤；Authorization 在日志中默认掩码 |
| **重连机制** | 复用项目已有 `jiuwenclaw:ws-reconnect-request` DOM 事件；视觉反馈复用连接状态灯 |

接入后，部署方无需修改任何 jiuwenclaw 代码即可在 UI 上配置请求扩展字段并验证整条透传链路。
