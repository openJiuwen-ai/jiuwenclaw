# JiuwenAvatar 企业模式单机部署与对外访问

> 企业版与单机开源版共用同一套代码，**靠环境变量切换**。  
> 未设置 `DEPLOYMENT_MODE=enterprise` 时，打开的是单机版（无租户登录）。  
> 完整 K8s 生产部署见 `deploy/enterprise/` 与上游企业部署工具；本文是**单机企业烟测**（可对外访问 + 租户登录）。

参考：[`JiuwenAvatar-分布式云化部署设计.md`](./JiuwenAvatar-分布式云化部署设计.md) §8.5 / §8.6。

## 1. 你会得到什么

企业模式下打开前端，会先进入 **「登录企业管理台」**：

- 输入 `用户 ID` + `租户/组织 ID`（本地 Identity shim，后续可换 OAuth2/JWT）
- 登录后侧边栏显示当前租户 / 用户
- 创建分身时自动带上 `group_id` / `user_id` / `service_id` 隔离上下文

当前阶段是**本地烟测 Identity**，不是完整 Manager SaaS 管控台（完整 Manager/WebUI 在 K8s 企业部署工具里）。

## 2. 环境要求

| 依赖 | 说明 |
|------|------|
| Python 3.11~3.13 + uv | 后端 |
| Node.js ≥ 18 | 前端 |
| Redis | 本机已有即可（`127.0.0.1:6379`）；也可用 JSON SessionMap |

## 3. 安全组端口（均在 20000~30000）

| 端口 | 是否必须对外 | 用途 |
|------|--------------|------|
| **29173** | ✅ | 前端（企业登录页 + 业务 UI） |
| **29000** | ✅ | Gateway WebSocket（登录/对话必需） |
| **29002** | ✅（HTTP 调分身时） | `POST /avatar/chat` |
| 29001 | 可选 | ACP / TUI |
| 28092 | ❌ | AgentServer（默认仅本机） |

最少放行：`29173`、`29000`（再加 `29002` 若要外部 HTTP 调分身）。

## 4. 首次安装

```bash
cd /path/to/jiuwenswarm
uv sync
uv run jiuwenavatar-init

cd jiuwenavatar/channels/web/frontend
npm install
cd -
```

并配置真实模型凭据（前端「配置信息」或 `~/.jiuwenavatar/config/.env`）。

## 5. 企业模式环境变量（关键）

推荐落到文件，例如 `~/.jiuwenavatar-enterprise/start.env`：

```bash
JIUWENAVATAR_ENTERPRISE_MODE=true
DEPLOYMENT_MODE=enterprise
AGENT_SERVER_DEPLOY_MODE=k8s

# 单机烟测：Redis SessionMap + JSON 存储（本机有 Redis 时）
GATEWAY_SESSION_MAP_BACKEND=redis
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
JIUWENAVATAR_STORE_BACKEND=json
JIUWENAVATAR_TENANT_WORKSPACE_ROOT=/home/jiuwen/.jiuwenavatar-enterprise/tenants

# 静态 AgentServer（无 K8s RuntimeManagement 时走默认 endpoint）
AGENT_SERVER_URL=ws://127.0.0.1:28092
AGENT_SERVICE_ENDPOINTS={}

# 对外绑定
WEB_HOST=0.0.0.0
AVATAR_HTTP_HOST=0.0.0.0
WEBHOOK_HOST=0.0.0.0
GATEWAY_HOST=0.0.0.0
```

若暂无 Redis，把 SessionMap 改成：

```bash
GATEWAY_SESSION_MAP_BACKEND=json
```

## 6. 拉起所有服务

```bash
mkdir -p ~/.jiuwenavatar-enterprise/tenants

# 清理端口（如有残留）
for port in 28092 29000 29001 29002 29173; do
  pids=$(lsof -ti "tcp:${port}" -sTCP:LISTEN 2>/dev/null || true)
  [ -n "$pids" ] && kill -9 $pids 2>/dev/null || true
done

cd /path/to/jiuwenswarm
set -a
source ~/.jiuwenavatar-enterprise/start.env
set +a

# 后端：AgentServer + Gateway（企业路由）+ Avatar HTTP
nohup uv run python -m jiuwenavatar.app \
  > /tmp/jiuwenavatar-backend.log 2>&1 &

# 等 Gateway
for i in $(seq 1 60); do
  curl -sf http://127.0.0.1:29002/avatar/health >/dev/null && break
  sleep 1
done

# 前端
cd jiuwenavatar/channels/web/frontend
nohup npx vite --host 0.0.0.0 --port 29173 \
  > /tmp/jiuwenavatar-frontend.log 2>&1 &
```

### 如何确认是企业模式

日志中应出现：

```text
[App] using RuntimeManagementAgentClient for enterprise routing
```

或用 WebSocket 查：

```bash
# manager.status 应返回 enterprise_mode=true, deployment_mode=enterprise
```

## 7. 使用方式

1. 浏览器打开：`http://<机器IP>:29173`
2. 看到 **登录企业管理台**（若仍是旧单机页，强制刷新 / 清站点缓存）
3. 输入例如：
   - 用户 ID：`local-user`
   - 租户/组织 ID：`default`
   - 角色：`member` 或 `org_admin`
4. 登录后进入分身页；「我的分身」卡片可看 **分身 ID** 并复制
5. HTTP 调分身：

```bash
curl -sS -X POST http://<机器IP>:29002/avatar/chat \
  -H 'Content-Type: application/json' \
  -d '{
    "avatar_id": "<分身ID或名称>",
    "params": {"query": "帮我检视xxxxxx"}
  }'
```

成功时只返回最终回复，例如：

```json
{"content": "……最终回答……"}
```

失败时：

```json
{"error": "……原因……"}
```

> 若分身触发「工具需授权」中断，HTTP 无法完成 Web 端确认交互；请在 **配置信息 → 安全配置**（org_admin）调整工具护栏，或在 Web 聊天中批准后再用 HTTP 提问。

更完整的**用户操作路径**（按身份登录 → 配模型 / GitCode Token / 安全策略 → HTTP 验收）见 [`企业单机烟测使用指导.md`](./企业单机烟测使用指导.md)。

## 8. 与「完整企业 K8s」的区别

| 能力 | 本文单机企业烟测 | K8s 企业生产（deploy 工具） |
|------|------------------|-----------------------------|
| 租户登录页 | ✅ Identity shim | ✅ + 正式认证 |
| 分身按租户隔离 | ✅ | ✅ |
| Manager 管控台 / 多服务 | ❌（本仓库烟测无独立 Manager Web） | ✅ |
| 动态创建 AgentServer Pod | ❌（静态 `AGENT_SERVER_URL`） | ✅ RuntimeManagement |
| Redis / PG / NFS | 可选本机 Redis + JSON | 一键部署组件 |

需要完整 Manager、多租户管控、动态 Runtime 时，请使用企业部署工具（K8s）或 `deploy/enterprise/jiuwenavatar-enterprise.yaml`。

## 9. 停止

```bash
pkill -f 'python3 -m jiuwenavatar' || true
pkill -f 'vite --host 0.0.0.0 --port 29173' || true
```
