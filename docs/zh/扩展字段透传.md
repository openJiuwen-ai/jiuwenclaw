# 扩展字段透传

## 模块定位

将一个 `dict[str, Any]` 类型的扩展字段从 Channel 入口贯穿到 Agent 执行阶段，供 Agent rail 读取，用于权限判定、租户隔离、审计标记等业务逻辑。

载体的键名和含义由部署方约定。框架不预设字段、不解析协议、不修改出站请求。

## 数据流

```
入站请求（HTTP header / WS query）
        │
        ▼  Channel 入口，按 forward_headers 抽取
ext: dict[str, Any]
        │
        ▼  写入 ContextVar；附到 Message.metadata["ext"]
Gateway / 跨进程
        │
        ▼  AgentServer 入口抬升回 ContextVar
Agent 执行循环
        │
        ▼
Agent rail：get_ext()
```

## 配置

通过环境变量声明要透传的字段名清单：

```bash
export JIUWENCLAW_REQUEST_EXT_FORWARD_HEADERS="Authorization,X-Tenant-Id"
```

| 变量 | 说明 |
|---|---|
| `JIUWENCLAW_REQUEST_EXT_FORWARD_HEADERS` | 逗号分隔的字段名清单。框架同时在入站 HTTP header 与 WS query 中按此清单（大小写不敏感）查找；命中即写入 ext dict，键名按本变量中的写法保留。未设或为空等价于关闭，框架全程 no-op。 |

### 三种声明入口的职责分工

| 入口 | 谁用 | 语义 |
|---|---|---|
| 环境变量 `JIUWENCLAW_REQUEST_EXT_FORWARD_HEADERS` | 部署 / 运维 | 启动时默认清单 |
| `register_forward_header(name)` / `register_forward_headers(names)` | 扩展加载时 | **加法**，去重累加；首次调用前以环境变量为底 |
| `set_forward_headers(headers)` | 管控面 / DB 监听器 | **整体覆盖**，替换运行时清单 |

读取优先级：

```
set_forward_headers / register_forward_header(s) 累积结果 > 环境变量 > 空（关闭）
```

### 扩展加载时声明字段（加法）

扩展代码在 `register_extensions(registry)` 中按业务需要声明本扩展所需字段，多个扩展独立声明、最终自动合并：

```python
# extensions/my_passthrough_ext/extension.py
from jiuwenclaw.extensions import ExtensionRegistry
from jiuwenclaw.request_ext import register_forward_header


async def register_extensions(registry: ExtensionRegistry):
    register_forward_header("Authorization")
    register_forward_header("X-Tenant-Id")
    return None
```

加载后，框架对所有入站请求按累积后的清单抽取 ext。

### 管控面 / DB 整体覆盖

```python
from jiuwenclaw.request_ext import set_forward_headers

# 管控面拉到新策略时调用，替换全部清单
set_forward_headers(["Authorization", "X-Tenant-Id", "X-User-Id"])

# 传 None 撤销覆盖，回落到环境变量
set_forward_headers(None)

# 传空 list 关闭透传
set_forward_headers([])
```

默认情况下框架不调用本接口。

## 公开 API

模块路径：`jiuwenclaw.request_ext`

| 名称 | 调用方 | 用途 |
|---|---|---|
| `build_ext_from_source(source)` | Channel | 从 HTTP header 或 WS query 字典按 forward_headers 抽取 ext。返回 dict 或 None。 |
| `set_current(ext)` | Channel | 将 ext 写入 ContextVar，返回还原 token。框架已在 Channel 握手处调用。 |
| `attach_to_metadata(metadata, ext=None)` | Channel | 将 ext 写入 `metadata["ext"]`；ext 缺省时读取 ContextVar。框架已在各 Message 构造点调用。 |
| `lift_from_metadata(metadata)` | AgentServer | 从 `request.metadata["ext"]` 抬升到 ContextVar，返回 token。框架已在 `AgentWebSocketServer._handle_message` 入口调用。 |
| `reset_ext(token)` | Channel / AgentServer | 与 `set_current` / `lift_from_metadata` 配对，请求结束还原 ContextVar。 |
| `get_ext()` | **Agent rail** | 返回当前请求的 ext dict；不存在时返回空 dict，调用方无需 None 检查。 |
| `register_forward_header(name)` | 扩展加载 | 加法注册一个字段名，去重累加。 |
| `register_forward_headers(names)` | 扩展加载 | 加法注册多个字段名，等价于循环调用 `register_forward_header`。 |
| `set_forward_headers(headers)` | 管控面 / DB | **整体覆盖** forward_headers 清单。传 None 撤销覆盖；传空 list 关闭透传。 |

常量 `METADATA_KEY = "ext"` —— ext 在 `Message.metadata` 中的固定键。

## 框架内部接入点（已完成）

| 位置 | 行为 |
|---|---|
| `jiuwenclaw/channel/vibeskill_channel.py` 握手 | 调 `build_ext_from_source(headers) or build_ext_from_source(query)` + `set_current(ext)` |
| `jiuwenclaw/channel/vibeskill_channel.py` 各 Message 构造 | `metadata=attach_to_metadata(metadata)` |
| `jiuwenclaw/channel/web_channel.py` 握手 | 同上（基于 WS query） |
| `jiuwenclaw/agentserver/agent_ws_server.py` `_handle_message` 入口 | `lift_from_metadata` + `try/finally: reset_ext` |

部署方无需修改框架代码；通过环境变量控制要透传的字段。

## Agent rail 消费侧

`get_ext()` 是部署方业务 rail 与扩展字段的唯一接触点。返回值始终为 dict（不存在时为空 dict）。

### 完整参考样例

下例实现"按租户隔离工具调用权限"。完整代码可直接拷贝到自定义 rail 扩展目录使用。

**文件位置**：`~/.jiuwenclaw/agent/jiuwenclaw_workspace/extensions/<rail_name>/rail.py`

```python
# rail.py
from __future__ import annotations

import logging

from openjiuwen.core.single_agent.rail.base import (
    AgentCallbackContext,
    DeepAgentRail,
    ToolCallInputs,
)

from jiuwenclaw.request_ext import get_ext

logger = logging.getLogger(__name__)


class CustomRail(DeepAgentRail):
    """按租户隔离工具调用权限。

    数据契约：
      - ext["X-Tenant-Id"]: 当前请求所属租户 ID（由 forward_headers 配置透传）
      - 部署方在本类内维护"租户 → 允许的工具白名单"映射
    """

    priority = 50

    _TENANT_TOOL_WHITELIST = {
        "acme": {"web_search", "skill.execute"},
        "globex": {"web_search"},
    }

    async def before_tool_call(self, ctx: AgentCallbackContext) -> None:
        if not isinstance(ctx.inputs, ToolCallInputs):
            return

        ext = get_ext()
        if not ext:
            return

        tenant_id = ext.get("X-Tenant-Id")
        if not tenant_id:
            return

        tool_name = ctx.inputs.tool_name
        whitelist = self._TENANT_TOOL_WHITELIST.get(tenant_id)
        if whitelist is None:
            return
        if tool_name not in whitelist:
            logger.warning(
                "[CustomRail] 拒绝工具调用：tenant=%s tool=%s",
                tenant_id, tool_name,
            )
            ctx.cancel(f"tool {tool_name!r} not allowed for tenant {tenant_id!r}")
```

### 触发机制

自定义 rail 由 `RailManager`（`jiuwenclaw/agentserver/extensions/rail_manager.py`）统一管理：

1. 启动时 `JiuWenClawDeepAdapter.load_user_rails()` 扫描扩展目录，加载所有 `enabled` 状态的 rail。
2. 每个 rail 实例被 `agent_instance.register_rail(...)` 挂载到 DeepAgent。
3. 运行期间，DeepAgent 执行循环按生命周期自动调用 rail 的钩子方法（`before_invoke` / `before_tool_call` / `after_tool_call` 等）。

部署方写好 rail 类、放入扩展目录、配置 `enabled: true`，框架自动加载与调度。

## 跨进程透传

`Message.metadata["ext"]` 在 Gateway → AgentServer（含 K8s 动态拉起的 AgentServer pod，由 `RuntimeManagementAgentClient` 转发）路径上随 `E2AEnvelope.channel_context` 完整序列化传递。AgentServer 入口反序列化后调 `lift_from_metadata` 写入本进程 ContextVar。两端 ContextVar 各自独立，仅通过协议字段中转，无共享内存或同进程假设。

## 行为约束

* `get_ext()` 永不返回 None。
* ContextVar 在 asyncio 任务级别自动隔离，并发请求互不干扰。
* `reset_ext` 在 `_handle_message` 的 `finally` 中调用，确保同一 WebSocket 连接内不同请求之间不发生 ext 泄漏。
* rail 仅消费 ext，不应通过本接口写回；如需写入 ext，应由 Channel 入口或独立请求处理流程负责。
