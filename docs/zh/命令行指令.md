## 命令行 / 通道控制指令说明

JiuwenClaw 支持通过「特殊前缀指令」控制会话和模式，最常用的是：

- `/new_session`：为当前通道切换到一个全新的 `session_id`
- `/mode plan` 或 `/mode agent`：切换当前通道的工作模式

这些指令由 Gateway 层的 `MessageHandler` 解析，**不会发给 Agent 本身**。

---

### 1. `/new_session` —— 新建会话 ID

**作用：**

- 针对受控通道（当前支持：`feishu` / `xiaoyi` / `dingtalk`），为该通道生成一个新的 `session_id`，形如：  
  - `feishu_<毫秒时间戳hex>_<随机hex>`
  - `xiaoyi_<毫秒时间戳hex>_<随机hex>`
  - `dingtalk_<毫秒时间戳hex>_<随机hex>`
- 后续从该通道进来的所有普通聊天消息，都会被强制覆盖为这个新的 `session_id`，从而在 `workspace/session/` 下形成一个新的会话目录。

**使用方式：**

- 在通道（飞书 / 小艺 / 钉钉）中，直接发送一条消息：

  ```text
  /new_session
  ```
![](../assets/images/命令行解析.jpg)

- Gateway 会：
  1. 拦截这条消息（不转发给 Agent）
  2. 为该 `channel_id` 生成新的 `session_id`
  3. 在当前会话里回复一条系统提示，例如：  
     `session_id 已变更为 feishu_17f2b4b32e0_ab12cd`

**注意事项：**

- `/new_session` 只会修改 **后续消息绑定的 session_id**，不会立刻创建目录；目录在真正用到（如 todo / 文件写入 / 显式创建 session）时按需生成。

---

### 2. `/mode` —— 切换通道模式（plan / agent）

**作用：**

- 为当前通道设置一个逻辑「模式」，用于告诉 Agent 是偏向：
  - `plan`：偏规划、解释、拆解任务（默认）
  - `agent`：偏自动执行、直接动手
- 模式信息会写入消息的 `params["mode"]` 中，Agent 在构造提示词和行为策略时可以使用。

**使用方式：**

- 在受控通道中发送：

  ```text
  /mode plan
  ```

  或

  ```text
  /mode agent
  ```

- Gateway 会：
  1. 识别这条消息为控制指令，不转发给 Agent
  2. 更新内部 `ChannelControlState.mode`
  3. 给当前会话回复一条系统提示，例如：  
     `mode 已变更为 agent`

**生效范围：**

- 模式是 **按通道维度** 存储的（`channel_id` → `mode`），同一通道的所有后续消息，都会自动带上当前模式。
- 前端 `config.yaml` 中的 `default_mode` 可设初始值，`MessageHandler` 启动时会读取。

---

### 3. `/view` 与 `/ls` —— 查看文件与列目录（CLI 文件命令）

**作用：**

- 在通道里以“命令行指令”的形式查看 Agent 工作区内的文件内容（`/view` 或别名 `/cat`）
- 列出指定目录下的文件与子目录（`/ls`）

这组命令的特点是：**由 Gateway 解析，但会转发到 AgentServer 执行**（与 `/new_session`、`/mode` 这类“纯 Gateway 控制指令”不同）。

---

#### 3.1 指令语法

**查看文件：**

```text
/view <path>
/cat <path>
```

可选参数（行范围）：

```text
/view <path> -n <lines>
/view <path> -f <from_line> -l <lines>
```

- `-f`：起始行号（1-based），默认 `1`
- `-l`：显示行数
- `-n`：显示行数（`-l` 的别名）
- 优先级：`-l` 与 `-n` 同时出现时，以 `-l` 为准（因为解析时 `lines = -l or -n`）

**列目录：**

```text
/ls
/ls <path>
```

- `<path>` 为空时等价于 `.`（当前根目录）

---

#### 3.2 处理链路（从消息到结果）

**1) Gateway：解析与转发**

- 入口：`jiuwenclaw/gateway/message_handler.py::_parse_cli_file_command()`
  - 识别 `/view`、`/cat`、`/ls` 并解析参数
- 转发：`jiuwenclaw/gateway/message_handler.py::_forward_cli_file_command()`
  - `/view` → `ReqMethod.CLI_FILE_VIEW`（`cli.file.view`）
  - `/ls` → `ReqMethod.CLI_FILE_LIST`（`cli.file.list`）
  - 通过 `E2AEnvelope.params` 传递：
    - `"path"`：字符串路径
    - `"params"`：`/view` 的行参数（`from_line`、`lines`），`/ls` 为空字典

**2) AgentServer：路由到文件服务**

- 入口：`jiuwenclaw/agentserver/interface.py::_handle_cli_file_command()`
  - 根据 `req_method` 调用：
    - `CLIFileService.handle_view_command(path, cmd_params)`
    - `CLIFileService.handle_ls_command(path)`

**3) 文件服务：路径解析、权限校验、读取与格式化**

- 实现：`jiuwenclaw/agentserver/cli_file_service.py`
- 核心流程（以 `/view` 为例）：
  - `resolve_path(path)`：将输入路径解析为绝对路径
  - `is_path_allowed(full_path)`：安全边界校验（只允许 `agent_root` 范围内路径）
  - 存在性/类型检查：是否存在、是否为文件
  - 大小限制：最大 1MB（`MAX_FILE_SIZE`）
  - 扩展名白名单：`ALLOWED_EXTENSIONS`
  - 读取文件并按行号格式化输出（最多显示 `MAX_DISPLAY_LINES` 行）

**4) Gateway：回填到通道**

- `MessageHandler` 收到 `AgentServer` 返回的 `payload` 后，将 `payload["content"]`（或错误信息）发送回当前通道。

---

#### 3.3 路径语义与安全边界

**路径语义：**

- 当前实现约定：**相对路径一律相对 `agent_root`**
- 支持 Windows 反斜杠输入：会先归一化为 `/`
- 允许传入绝对路径，但最终仍会被安全边界限制（见下）

**安全边界（强约束）：**

- `CLIFileService.is_path_allowed()` 只允许访问 `agent_root` 目录树下的路径
- 因此即使用户传入绝对路径（例如系统盘路径），也会被拒绝

---

#### 3.4 返回格式

**`/view` 返回：**

- `payload["content"]` 为一个包含代码块的 Markdown 文本，形如：
  - 三引号代码块（每行带行号）
  - 末尾附带摘要：文件路径、总行数、显示范围等

**`/ls` 返回：**

- `payload["content"]` 为 Markdown 文本，包含：
  - 目录名
  - 子目录列表（带 `/`）
  - 文件列表（含格式化大小）
  - 统计汇总（目录数/文件数）

---

#### 3.5 失败场景（常见错误）

- 路径解析失败：`路径解析失败: ...`
- 越权访问：`路径不在允许访问范围内`
- 文件/目录不存在：`文件不存在: ...` / `目录不存在: ...`
- 类型不匹配：`不是文件: ...` / `不是目录: ...`
- 文件过大：超过 1MB
- 不支持的文件类型：扩展名不在白名单
