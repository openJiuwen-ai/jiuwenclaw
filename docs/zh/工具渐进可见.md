# 工具渐进可见：让模型只看到当前需要的工具

当 JiuwenClaw 接入较多内置工具、技能工具或 MCP 工具后，每次模型调用都携带完整工具 schema 会带来两个问题：上下文 token 占用变高，模型也更容易在大量工具中选错。工具渐进可见机制用于压缩模型侧的 `tools` 列表：常驻工具直接可见，其余已注册工具通过 `tools_search` + `invoke_tool` 按需访问。

这项能力只改变“哪些工具 schema 发送给模型”，不改变工具注册、权限校验和真实执行链路。MCP 仍按现有流程注册和连接。

## 工作方式

启用后，系统会把工具分为两类：

| 类型 | 说明 |
| :--- | :--- |
| 常驻可见工具 | 配置在 `eager_tools` 中，每轮模型调用都会带完整 schema，可直接调用 |
| 按需可见工具 | 已注册在运行时，但不出现在模型 `tools` 列表中；在系统 prompt 的「按需可见工具导航」中列出摘要 |

模型侧 `tools` schema **固定为** `eager_tools`（有利于 LLM 前缀缓存）。使用按需可见工具时：

1. 调用 `tools_search`，传入与导航列表一致的 `tool_name`，获取完整 `input_schema`
2. 调用 `invoke_tool`，传入精确 `tool_name` 与 `arguments`

无需把按需工具加载进下一轮 schema。

## 配置方式

配置位于 `config.yaml` 的 `react.tool_lazy_load`（与 `config.yaml` 中默认示例一致）：

```yaml
react:
  tool_lazy_load:
    enabled: true
    # Substring whitelist on model_name; empty = all models. Non-matching models see full tools.
    enable_for_models:
      - glm
    eager_tools:
      - tools_search
      - invoke_tool
      - bash
      - read_file
      # ...
    subagents:
      enabled: true
      inherit_parent_eager_tools: false
      eager_tools:
        - tools_search
        - invoke_tool
```

### 主开关

| 配置项 | 说明 |
| :--- | :--- |
| `enabled` | 是否启用工具渐进可见 |

### 模型白名单

| 配置项 | 说明 |
| :--- | :--- |
| `enable_for_models` | 模型名子串白名单（忽略大小写）。**空列表**表示所有模型均启用渐进可见；**非空**时仅命中的模型过滤 schema，未命中模型仍看到完整 tools 列表 |

日志 `[ProgressiveToolRail] lazy load bypassed for model=...` 表示当前模型未命中白名单、已跳过过滤。

关闭 `enabled` 后，模型调用会看到完整工具列表。

### 常驻可见工具

`eager_tools` 声明每轮都暴露给模型的工具。系统会自动补齐 `tools_search` 与 `invoke_tool`。

| 工具类型 | 建议 |
| :--- | :--- |
| 工具发现与调用 | `tools_search`、`invoke_tool`（自动补齐） |
| 用户交互 | `ask_user_question` |
| 文件与命令 | 常用文件读写、搜索、shell 工具 |
| 子 Agent | `spawn_subagent`、`fork_agent`（主 Agent 需要委托时） |

按需可见工具 = 已注册工具 − `eager_tools`，无需单独配置列表。

## 子 Agent 行为

`spawn_subagent` / `fork_agent` 可通过 `subagents.enabled` 单独启用。子 Agent 默认会从 `eager_tools` 中排除 `spawn_subagent`、`fork_agent`（避免嵌套委托）。每个子 Agent 使用 `agent_id=task_id` 注册独立的 meta 工具实例。

## 排查方式

关键日志前缀：`[ProgressiveToolRail]`

| 日志片段 | 含义 |
| :--- | :--- |
| `enabled profile=...` | 主 Agent 或子 Agent 已挂载 rail |
| `invoke total=... eager=... deferred=...` | 已注册 / 常驻 / 按需可见工具数量 |
| `filter tools X -> Y` | 发给模型前的 schema 过滤 |
| `lazy load bypassed for model=...` | 当前模型未命中 `enable_for_models`，未过滤 schema |
| `search tool_name=... matches=...` | `tools_search` 按注册名精确查找 |

## 常见问题

### 为什么模型会先调用 `tools_search` / `invoke_tool`？

目标工具不在当前 `tools` schema 中，必须通过 meta 工具间接调用。

### 是否会影响工具权限？

不会。只控制模型侧 schema 与导航提示，不绕过权限 rail 或 disabled tools。

### 与旧版 `search_and_load_tools` 方案的区别？

当前实现为**固定 schema + meta 工具间接调用**，不再把按需工具动态加入下一轮 `tools` 列表；配置键仍为 `tool_lazy_load`，实现类为 `JiuWenProgressiveToolRail`。
