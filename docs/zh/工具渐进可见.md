# 工具渐进可见：让模型只看到当前需要的工具

当 JiuwenClaw 接入较多内置工具、技能工具或 MCP 工具后，每次模型调用都携带完整工具 schema 会带来两个问题：上下文 token 占用变高，模型也更容易在大量工具中选错。工具渐进可见机制用于压缩模型侧的 `tools` 列表，让常用工具直接可见，其余工具通过 `search_and_load_tools` 按需搜索和加载。

这项能力只改变“哪些工具 schema 发送给模型”，不改变工具注册、权限校验和真实执行链路。本版也不会延迟连接 MCP server，MCP 仍按现有流程注册和连接。

## 工作方式

启用后，系统会把工具分为两类：

| 类型 | 说明 |
| :--- | :--- |
| 常驻可见工具 | 配置在 `eager_tools` 中，每轮模型调用都会带完整 schema，适合文件、命令、子 Agent、技能、用户确认等高频工具 |
| 按需可见工具 | 已经注册在运行时，但默认不出现在模型 `tools` 列表中，需要先调用 `search_and_load_tools` 搜索并加载 |

模型如果需要当前不可见的能力，会先调用 `search_and_load_tools`。该工具会在已注册工具中检索匹配项，并把命中的工具加入当前 session 的可见工具集合。下一轮模型调用时，这些工具会出现在 `tools` 列表中，模型即可直接调用真实工具。

## 配置方式

配置位于 `config.yaml` 的 `react.tool_lazy_load`：

```yaml
react:
  tool_lazy_load:
    enabled: true
    search_max_results: 5
    default_load_limit: 3
    max_loaded_tools: 1024
    defer_mcp: false
    defer_builtin: false
    eager_tools:
      - search_and_load_tools
      - ask_user_question
      - spawn_subagent
      - fork_agent
      - read_file
      - write_file
      - edit_file
      - grep
      - glob
      - bash
    subagents:
      enabled: true
      inherit_parent_eager_tools: false
      eager_tools:
        - search_and_load_tools
```

### 主开关

| 配置项 | 说明 |
| :--- | :--- |
| `enabled` | 是否启用工具渐进可见。`true` 启用，`false` 关闭 |
| `JIUWENCLAW_TOOL_LAZY_LOAD` | 环境变量覆盖项，支持 `true` / `false` |

关闭后，系统回到原有行为，模型调用会看到完整工具列表。

### 搜索和加载参数

| 配置项 | 说明 |
| :--- | :--- |
| `search_max_results` | `search_and_load_tools` 单次搜索最多返回的候选工具数 |
| `default_load_limit` | 模型调用 `search_and_load_tools` 时未显式传 `limit`，默认加载的 Top N 工具 |
| `max_loaded_tools` | 当前 session 中最多保留的按需可见工具数 |

当按需加载后的可见工具数超过 `max_loaded_tools` 时，系统会保留前面的工具，超出的工具会进入 `skipped_tools`，不会在下一轮模型调用中变为可调用。常驻可见工具仍由 `eager_tools` 保证可见。

### 常驻可见工具

`eager_tools` 用于声明首轮就应该完整暴露给模型的工具。建议至少保留：

| 工具类型 | 建议 |
| :--- | :--- |
| 工具发现 | `search_and_load_tools` 必须保留，否则模型无法加载隐藏工具 |
| 用户交互 | `ask_user_question` |
| 文件与命令 | 常用文件读写、搜索、shell 工具 |
| 子 Agent | `spawn_subagent`、`fork_agent`，如果希望主 Agent 能委托任务 |
| 技能工具 | 如果技能是核心能力，可保留 `skill_tool`、`skill_complete` |

如果 `eager_tools` 中误删了 `search_and_load_tools`，系统会自动把它补回常驻可见集合。

## 子 Agent 行为

`spawn_subagent` 和 `fork_agent` 创建的子 Agent 也可以启用工具渐进可见：

```yaml
subagents:
  enabled: true
  inherit_parent_eager_tools: false
  eager_tools:
    - search_and_load_tools
```

| 配置项 | 说明 |
| :--- | :--- |
| `subagents.enabled` | 是否对子 Agent 启用工具渐进可见 |
| `subagents.inherit_parent_eager_tools` | 是否沿用主 Agent 的 `eager_tools` |
| `subagents.eager_tools` | 子 Agent 自己的常驻可见工具 |

默认建议子 Agent 更保守，只保留 `search_and_load_tools`。这样子 Agent 继承父 Agent 工具后，不会一次性把大量工具 schema 发送给模型。每个子 Agent task 使用独立 session，已加载工具状态不会污染父 Agent 或其他子 Agent。

## 和 MCP 懒加载的区别

当前版本只做模型侧工具可见性压缩：

| 能力 | 当前版本 |
| :--- | :--- |
| 减少 LLM 请求中的 tools schema | 支持 |
| 降低工具选择噪声 | 支持 |
| 启动时不连接 MCP server | 不支持 |
| MCP catalog-only 索引 | 不支持 |
| MCP 首次命中后再连接 | 不支持 |

因此，如果系统启动慢是由 MCP server 连接导致的，这项能力不会直接减少启动耗时；它主要减少模型调用时的工具 schema token 和工具选择噪声。

## 排查方式

关键日志统一使用 `[ProgressiveTool]` 前缀：

| 日志片段 | 含义 |
| :--- | :--- |
| `enabled profile=...` | 已为主 Agent 或子 Agent 挂载渐进可见 rail |
| `invoke registered=... visible=... always=...` | 本轮已注册工具数、当前 session 可见工具数、常驻可见工具数 |
| `filter tools X -> Y` | 模型调用前工具列表被过滤，`X` 是过滤前数量，`Y` 是过滤后数量 |
| `search_and_load query=... matched=... loaded=... skipped=...` | 模型调用 `search_and_load_tools` 后的搜索、加载和截断结果 |

如果需要查看最终发送给模型的完整 messages 和 tools，可在调试环境开启 LLM IO trace。日常排查通常先看 `[ProgressiveTool]` 日志即可。

## 常见问题

### 为什么模型会先调用 `search_and_load_tools`？

因为目标能力对应的真实工具当前不可见。模型需要先搜索并加载工具，下一轮才能直接调用真实工具。这是为了减少首轮工具 schema 占用。

### 为什么工具搜索到了，但下一轮还是不可调用？

优先检查 `search_and_load_tools` 返回的 `skipped_tools`。如果加载后超过 `max_loaded_tools`，超出的工具会被跳过，不会进入下一轮模型 `tools` 列表。

### 是否会影响工具权限？

不会。工具渐进可见只控制模型是否看到工具 schema，不绕过原有权限 rail、disabled tools 配置和真实工具执行逻辑。

### 是否会影响不同 session？

不会。已加载工具状态存放在 session state 中，不同用户会话、主 Agent 和子 Agent task 之间相互隔离。
