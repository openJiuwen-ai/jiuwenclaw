# 心跳任务与健康检查

[English](../en/Heartbeat.md)

JiuwenSwarm 将会话续跑、独立定时执行和服务探活明确分成三种能力。

| 能力 | Heartbeat 心跳任务 | Cron 定时任务 | HealthCheck 健康检查 |
|------|--------------------|---------------|----------------------|
| 主要用途 | 回到原会话继续上下文任务 | 到点启动独立任务 | 检查 Gateway 与 AgentServer 连通性 |
| 执行上下文 | 原 `channel_id + session_id` | 独立执行上下文 | 临时系统探活请求 |
| 是否调用 Agent | 是 | 是 | 否，只返回 `HEALTH_CHECK_OK` |
| 历史记录 | 保留在原会话中 | 保留在定时任务记录中 | 不进入普通会话历史 |
| 用户任务来源 | 创建任务时保存的 prompt | Cron 任务描述 | 无，不读取 `HEARTBEAT.md` |

## Heartbeat 心跳任务

Heartbeat 是绑定当前会话的自动续跑任务。触发时，Gateway 使用普通
`chat.send` 请求把任务 prompt 投递回原 Session，并通过
`metadata.automation.kind=heartbeat` 标识自动执行来源。它不会创建独立会话，
也不会使用特殊的底层 `RunKind`。

### 忙会话处理

如果触发时原 Session 正在执行用户任务，Heartbeat 不会抢占或取消该任务，
而是等待 Session 空闲。默认最多等待 60 秒；超时后本次执行记为 `skipped`，
周期任务继续等待下一次调度。该等待规则与 `concurrency_policy` 相互独立：
后者只控制多个 Heartbeat 运行彼此重叠时采用 `skip`、`queue` 还是 `replace`。

Heartbeat 的用户消息、助手回复、工具调用和自动化元数据都会写入原 Session
历史。刷新或重新打开 Session 后，可以看到以前的 Heartbeat 执行记录。

### 调度类型

- `interval`：固定间隔，默认最小间隔为 60 秒。
- `cron`：5 字段 Cron 表达式，可指定 IANA 时区。
- `once`：指定 Unix 时间戳执行一次。

任务默认最多运行 12 次。任务可设置 `max_runs=null` 表示不限制，但应谨慎使用。
任务状态包括 `scheduled`、`running`、`completed`、`expired` 和 `disabled`。

### 资源配置

```yaml
heartbeat:
  jobs:
    min_interval_seconds: 60
    max_active_jobs_per_session: 5
    max_active_jobs_global: 100
    default_max_runs: 12
    default_concurrency_policy: skip
    default_session_deleted_policy: disable
```

对应环境变量为：

- `HEARTBEAT_JOBS_MIN_INTERVAL`
- `HEARTBEAT_JOBS_MAX_ACTIVE_PER_SESSION`
- `HEARTBEAT_JOBS_MAX_ACTIVE_GLOBAL`
- `HEARTBEAT_JOBS_DEFAULT_MAX_RUNS`
- `HEARTBEAT_JOBS_DEFAULT_CONCURRENCY_POLICY`
- `HEARTBEAT_JOBS_DEFAULT_SESSION_DELETED_POLICY`

Heartbeat 任务保存在用户数据目录的 `heartbeat_jobs.json` 中。文件损坏或不可读
时，Heartbeat 调度会停用并记录错误，但不会阻止 Gateway、Cron 或普通 Channel
启动。

### Web/RPC 接口

- `heartbeat.job.list`
- `heartbeat.job.meta`
- `heartbeat.job.get`
- `heartbeat.job.create`
- `heartbeat.job.update`
- `heartbeat.job.delete`
- `heartbeat.job.toggle`
- `heartbeat.job.preview`
- `heartbeat.job.run_now`
- `heartbeat.job.cancel`

Agent 也可以在当前会话中使用对应的 `heartbeat_*` 工具创建和管理任务。普通
接口只能访问当前 Session 绑定的任务。

## HealthCheck 健康检查

HealthCheck 是原探活机制的新名称，只检查服务连通性，不执行用户任务。

```yaml
health_check:
  every: 3600
  target: web
  active_hours:
    start: 08:00
    end: 22:00
```

推荐环境变量为 `HEALTH_CHECK_INTERVAL`、`HEALTH_CHECK_RELAY_CHANNEL_ID` 和
`HEALTH_CHECK_TIMEOUT`。旧 `HEARTBEAT_*` 环境变量仅作为迁移期读取兼容。

公开接口和事件使用：

- `health_check.get_conf`
- `health_check.set_conf`
- `health_check.relay`

启动时，旧 `heartbeat.every/target/active_hours` 会迁移到 `health_check`，并保留
`heartbeat.jobs`。后续写入只使用新名称。升级时建议 Gateway 与 AgentServer
整体升级；必须分批时，应先升级 AgentServer，再升级 Gateway。

绑定 Session 的 Heartbeat 任务当前要求本机 WebSocket AgentServer 与共享的
Session 存储。其他部署类型会明确拒绝 Heartbeat 任务操作，避免接受无法安全
续跑 Session 的任务。

## Cron 定时任务

Cron 仍保持独立调度、独立执行上下文和原有 `cron.job.*` 接口。Heartbeat
重构不会把 Cron 任务绑定到聊天 Session，也不会改变 Cron 的 5/7 字段兼容规则。
