# JiuwenAvatar 用户使用指导（企业单机烟测）

面向**使用者**：如何按身份登录、配模型、配 GitCode Token、调安全策略，再用后端接口验证分身。

服务已由管理员拉起时，默认访问：

| 入口 | 地址 |
|------|------|
| Web 前端 | `http://<机器IP>:29173` |
| Avatar HTTP | `http://<机器IP>:29002/avatar/chat` |

部署/端口/环境变量见 [`单机部署与对外访问.md`](./单机部署与对外访问.md)。

---

## 使用流程一览

```text
① 选身份登录
    ↓
② 配置大模型（并「测试」通过）
    ↓
③ 配置 GitCode Token（需要检视 PR / Issue 时）
    ↓
④（管理员）配置安全策略
    ↓
⑤ 创建 / 选用分身，复制分身 ID
    ↓
⑥ 用后端 HTTP 接口提问验证
```

---

## ① 区分身份登录

打开 `http://<机器IP>:29173`，进入 **「登录企业管理台」**。

| 字段 | 填什么 | 说明 |
|------|--------|------|
| 用户 ID | 如 `admin` / `alice` | 本地烟测任意非空字符串即可 |
| 租户/组织 ID | 如 `openJiuwen` / `default` | 同一租户下的用户共享租户数据隔离边界 |
| 角色 | 见下表 | **决定你能改什么配置** |

### 角色怎么选

| 角色 | 适合谁 | 能做什么 |
|------|--------|----------|
| **`org_admin`** | 管理员 / 首次配置的人 | 配置**大模型目录**、**安全配置**（工具护栏）、看租户级配置；建议先用这个完成 §②④ |
| **`member`** | 普通使用者 | 选默认模型、配**个人**项（如 GitCode Token）；**看不到**「安全配置」Tab |

建议：

1. 第一次用 **`org_admin`** 登录，把模型、安全策略配好并保存。  
2. 再用 **`member`** 登录体验普通用户视角（确认安全 Tab 不可见、个人 Token 可配）。

登录成功后，侧栏会显示当前 **租户 / 用户**。

## ② 配置大模型

路径：**配置信息 → 模型配置**

1. 填写（或编辑）默认模型：
   - **api_base**：如 `http://<LiteLLM主机>:8080/v1`
   - **api_key**：模型服务密钥  
     - 若是 **LiteLLM Proxy**，必须填该 proxy 后台签发的 **virtual key**（不是随便一把上游厂商 Key）
   - **model**：如 `GLM-5.2`
   - **model_provider**：一般选 `OpenAI`（兼容 OpenAI 协议时）
2. 点 **「测试」/「校验模型」**，应提示成功。  
3. **保存**。

### 自检失败时

| 现象 | 含义 | 怎么办 |
|------|------|--------|
| 超时 / 连不上 | 后端访问不到 `api_base` | 查网络、防火墙、地址是否含 `/v1` |
| `401` / `token_not_found_in_db` | Key 对该 LiteLLM **无效** | 在 LiteLLM 管理台换一把有效 virtual key，再保存并重测 |
| 测试成功但对话仍失败 | 分身未用该默认模型，或会话缓存旧配置 | 新开会话；确认模型列表里该项为默认 |

> 模型请求由**后端**发出，不是浏览器直连；本机网络通 ≠ 服务器能访问模型地址。

## ③ 配置 GitCode Token

需要分身调用 **gitcode-repo** 相关能力（PR 检视意见、Issue 评论等）时再配。

路径：**配置信息 → 其他配置 → 第三方服务配置**（或搜索 **GitCode Token**）

1. 打开 GitCode：**设置 → 个人访问令牌**，创建 Token。  
2. 粘贴到页面的 **GitCode Token** 输入框。  
3. **保存**。

说明：

- **member** 与 **org_admin** 一般都能配自己的 Token（企业模式下为用户级配置）。  
- Token 只保存在服务端配置中，不要发到群聊或贴进 Issue。

## ④ 配置安全策略（仅 org_admin）

路径：**配置信息 → 安全配置**

普通 **member 登录看不到此 Tab**，属预期。

建议按使用场景调整：

| 目标 | 建议 |
|------|------|
| Web 里人工确认即可 | 保持工具默认 `ask`；需要时在弹窗点允许 |
| HTTP 接口要一口气答完、少中断 | 将常用只读工具（如 `grep`、`read_file`）改为 **`allow`**，或对外部目录规则放宽 |
| 收紧生产风险 | 高危 shell 保持 `deny` / `ask`；不要对整库 `bash` 无脑 `allow` |

常见项：

- **工具安全护栏总开关**（`permissions_enabled`）
- **工具级** allow / ask / deny（`PermissionsToolsEditor`）
- **外部目录**（workspace 外路径默认常为 `ask`）

改完后务必 **保存**。  
若 HTTP 提问总返回「需要授权后才能继续」，优先回这里放行对应工具，或先在 Web 聊天里批准一次。

## ⑤ 创建 / 选用分身

路径：侧栏 **「我的分身」**（或数字分身中心）

1. 创建分身（名称自定，如 `committerXXX`）。  
2. 在卡片上查看 **分身 ID**（形如 `avatar-xxxxxxxx`），点复制。  
3. 后续 HTTP 调用优先用这个 **ID**（也可用名称，服务端会解析）。

企业模式下，分身会带上当前登录的租户 / 用户隔离上下文。

## ⑥ 用后端接口测试

### 健康检查

```bash
curl -sS "http://<机器IP>:29002/avatar/health"
```

期望：

```json
{"status": "ok", "avatar_http": true}
```

### 向分身提问

```bash
curl -sS -X POST "http://<机器IP>:29002/avatar/chat" \
  -H "Content-Type: application/json" \
  -d '{
    "avatar_id": "avatar-xxxxxxxx",
    "params": {
      "query": "用一句话介绍你自己"
    }
  }'
```

也可用分身名称：

```bash
-d '{"avatar_id":"committerXXX","params":{"query":"你好"}}'
```

### 如何判断成功

| 响应 | 含义 |
|------|------|
| `{"content":"……中文回答……"}` | 成功；只要最终回复文本 |
| `{"error":"..."}` | 失败；看 error 文案 |
| content 提示「需要授权…工具 xxx」 | 安全策略拦了工具；回 §④ 或改用 Web 批准后再测 |

建议验收顺序：

1. 先问一句闲聊（不触发工具）→ 确认模型链路 OK。  
2. 再问依赖检索/仓库的问题 → 确认 Token、安全策略、Skill 是否齐。  
3. 问「企业版 / K8s 部署」类问题 → 应走预置 skill 的 `enterprise_kub` 索引（需已拉取对应 assets，见下）。

## 附录 A：预置 Swarm QA Skill（可选）

分身若加载了 `openjiuwen-jiuwenswarm`：

| 问题类型 | 索引 |
|----------|------|
| 未指定版本的开源 Swarm | `0.2.3`（分支 `dev_release_0.2.3`） |

```bash
bash openjiuwen-jiuwenswarm/scripts/fetch.sh 0.2.3
bash openjiuwen-jiuwenswarm/scripts/fetch.sh enterprise_kub
```

## 附录 B：常见问题速查

| 现象 | 处理 |
|------|------|
| 没有登录页 | 未开企业模式；找管理员按部署文档启动 |
| 看不到「安全配置」 | 用 **org_admin** 重新登录 |
| 模型测试 401 | 换有效 LiteLLM virtual key |
| HTTP 只有授权中断、没有最终答案 | 调安全策略或改 Web 端批准 |
| curl 中文是 `\uXXXX` | 后端版本过旧；需含 UTF-8 输出的 Gateway |
| 分身答仍引用 0.2.2 | 同步了索引但未拉 `assets/0.2.3` |
