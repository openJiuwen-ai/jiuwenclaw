# JiuwenAvatar 企业单机烟测使用指导

本文面向：**在一台机器上拉起企业模式 Avatar，对外访问前端，并用 HTTP 调用分身**。  
更完整的端口/环境变量说明见 [`单机部署与对外访问.md`](./单机部署与对外访问.md)。

---

## 1. 快速路径（你要做的事）

| 步骤 | 做什么 |
|------|--------|
| 1 | 配好模型 `API_BASE` / `API_KEY` / `MODEL_NAME`（LiteLLM 需 **该 proxy 的 virtual key**） |
| 2 | `source` 企业模式 `start.env`，启动后端 + 前端 |
| 3 | 浏览器打开 `http://<IP>:29173`，用 **org_admin** 登录 |
| 4 | 「我的分身」创建/选用分身，复制 **分身 ID** |
| 5 |（可选）`curl` `POST :29002/avatar/chat` 提问 |

---

## 2. 启动与登录

### 2.1 环境变量（示例）

```bash
# ~/.jiuwenavatar-enterprise/start.env
JIUWENAVATAR_ENTERPRISE_MODE=true
DEPLOYMENT_MODE=enterprise
AGENT_SERVER_DEPLOY_MODE=k8s
GATEWAY_SESSION_MAP_BACKEND=redis
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
JIUWENAVATAR_STORE_BACKEND=json
JIUWENAVATAR_TENANT_WORKSPACE_ROOT=$HOME/.jiuwenavatar-enterprise/tenants
AGENT_SERVER_URL=ws://127.0.0.1:28092
AGENT_SERVICE_ENDPOINTS={}
WEB_HOST=0.0.0.0
AVATAR_HTTP_HOST=0.0.0.0
WEBHOOK_HOST=0.0.0.0
GATEWAY_HOST=0.0.0.0
```

### 2.2 启动

```bash
cd /path/to/jiuwenswarm
set -a && source ~/.jiuwenavatar-enterprise/start.env && set +a
nohup uv run python -m jiuwenavatar.app > /tmp/jiuwenavatar-backend.log 2>&1 &

cd jiuwenavatar/channels/web/frontend
nohup npx vite --host 0.0.0.0 --port 29173 > /tmp/jiuwenavatar-frontend.log 2>&1 &
```

健康检查：

```bash
curl -sS http://127.0.0.1:29002/avatar/health
# {"status":"ok","avatar_http":true}
```

### 2.3 登录

打开 `http://<机器IP>:29173` → **登录企业管理台**：

| 字段 | 示例 | 说明 |
|------|------|------|
| 用户 ID | `local-user` | 任意非空字符串（本地 Identity shim） |
| 租户/组织 ID | `openJiuwen` / `default` | 租户隔离键 |
| 角色 | **`org_admin`** | 才能看到「安全配置」、改全局护栏 |

侧栏「我的分身」卡片上可查看并复制 **分身 ID**（形如 `avatar-xxxxxxxx`）。

## 3. HTTP 调用分身

### 3.1 请求

```bash
curl -sS -X POST "http://<机器IP>:29002/avatar/chat" \
  -H "Content-Type: application/json" \
  -d '{
    "avatar_id": "avatar-xxxxxxxx",
    "params": { "query": "你好，用一句话介绍你自己" }
  }'
```

也可用分身**名称**代替 ID（服务端会解析）。兼容拼写：`atavar_id`。

### 3.2 响应（只返回最终回复）

成功：

```json
{"content": "……最终回答……"}
```

失败：

```json
{"error": "……原因……"}
```

说明：

- 响应为 **UTF-8 可读中文**（不再是 `\uXXXX`）。
- 若触发工具授权中断，HTTP **无法**像 Web 那样点「批准」；请先在 Web 聊天批准，或在安全配置里放宽对应工具后再调 HTTP。

### 3.3 端口

| 端口 | 用途 |
|------|------|
| 29173 | 前端 |
| 29000 | Gateway WebSocket |
| 29002 | Avatar HTTP |
| 28092 | AgentServer（默认仅本机） |

## 4. 安全配置（工具护栏）

企业模式下：

- **org_admin**：配置信息里有 **「安全配置」** Tab（工具安全护栏 / permissions）
- **member**：不显示安全 Tab（仅模型/个人配置）

路径：**配置信息 → 安全配置**。

若 HTTP 提问总卡在「工具需授权」，可在此将相关工具改为 `allow`，或在 Web 端对当次调用选择「总是允许」。

---

## 5. 模型配置注意

- 测试模型走的是 **后端** 访问 `API_BASE`，不是浏览器直连。
- 若 `API_BASE` 是 LiteLLM Proxy，Key 必须是该 proxy 的 **virtual key**；出现 `token_not_found_in_db` 表示 Key 对该 proxy 无效，不是 Avatar 编码问题。
- 本机可用下面命令自检（不要把真实 Key 贴进聊天）：

```bash
curl -sS "$API_BASE/models" -H "Authorization: Bearer $API_KEY"
```

## 6. 预置 QA Skill（JiuwenSwarm 问答）

内置技能包：`openjiuwen-jiuwenswarm`（由 `openjiuwen-qa-guideline` 路由）。

| 场景 | 使用的 reference | Git 源 |
|------|------------------|--------|
| 未指定版本的开源 Swarm 问题 | **`0.2.3`**（当前最新） | 分支 `dev_release_0.2.3` |
| 企业版 / 企业 claw / 企业 swarm / K8s 企业部署 | **`enterprise_kub`** | 分支 `dev/enterprise_kub` |

### 6.1 补齐源码快照（重要）

只有 `references/*.md` **不够**，还需要 `assets/<索引名>/`：

```bash
# 在分身工作区 skills 目录，或仓库预置 skill 目录
cd <...>/skills   # 或 jiuwenavatar/resources/avatar-skills

bash openjiuwen-jiuwenswarm/scripts/fetch.sh 0.2.3
bash openjiuwen-jiuwenswarm/scripts/fetch.sh enterprise_kub
# 或批量：bash openjiuwen-jiuwenswarm/scripts/fetch.sh auto
```

拉取脚本会读 reference 顶部的 `<!-- git-ref: ... -->` 再浅克隆。

### 6.2 改完预置 skill 后

仓库里的 `jiuwenavatar/resources/avatar-skills/` 是源；运行中的分身读的是租户工作区里的副本。更新预置后请同步到对应分身的：

```text
~/.jiuwenavatar-enterprise/tenants/<租户>/<用户>/<avatar-id>/agent/workspace/skills/
```

## 7. 常见问题

| 现象 | 处理 |
|------|------|
| 打开仍是单机页、无登录 | 确认已 `source` 企业 env 再启后端；浏览器强刷 |
| 无「安全配置」 | 用 **org_admin** 登录 |
| curl 返回一堆 `\uXXXX` | 需含 UTF-8 dumps 的后端版本；升级/重启 Gateway |
| curl 返回很长 payload | 需「只返回 content」的后端版本 |
| 问答仍引用 0.2.2 | 同步了 reference 但未拉 `assets/0.2.3`，执行 §6.1 |
| 模型 401 `token_not_found_in_db` | 换 LiteLLM 有效 virtual key |
