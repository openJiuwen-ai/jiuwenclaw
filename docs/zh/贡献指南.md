# 贡献指南

> 感谢您对 JiuwenClaw 的关注！本文档帮助您了解如何参与项目贡献。

## 1. 项目概述

JiuwenClaw 是一个自托管的 AI Agent 系统，基于华为 `openjiuwen` 框架构建，使用 Python 3.11+ 开发。

- **仓库**: [GitHub](https://github.com/huawei-labs/jiuwenclaw)（或对应内部仓库）
- **License**: Apache 2.0
- **Python 版本**: 3.11, 3.12, 3.13

## 2. 开发环境搭建

### 2.1 前置要求

- Python 3.11+
- Git
- 推荐：`uv` (快速 Python 包管理器)

### 2.2 克隆与安装

```bash
# 克隆仓库
git clone <repository-url>
cd jiuwenclaw

# 创建虚拟环境（推荐）
python -m venv .venv
source .venv/bin/activate  # Linux/Mac
# 或
.venv\Scripts\activate     # Windows

# 安装可编辑模式（包含开发依赖）
pip install -e ".[test]"

# 或使用 uv（更快）
uv pip install -e ".[test]"
```

### 2.3 初始化工作区

```bash
# 初始化 JiuwenClaw 工作区（交互式）
jiuwenclaw-init

# 或手动配置
cp jiuwenclaw/resources/config.yaml ~/.jiuwenclaw/config/config.yaml
cp jiuwenclaw/resources/.env.template ~/.jiuwenclaw/config/.env
# 编辑 .env 填入 API Key 等配置
```

### 2.4 启动开发服务

```bash
# 启动后端服务（Gateway + Agent）
jiuwenclaw-app

# 启动 Web 前端
jiuwenclaw-web

# 或一键启动所有服务
jiuwenclaw-start
```

## 4. 开发工作流

### 4.1 分支策略

- `main` — 稳定发布分支
- `develop` — 开发主分支
- `feature/<name>` — 功能开发分支
- `fix/<name>` — 修复分支
- `release/<version>` — 发布准备分支

### 4.2 贡献流程

```bash
# 1. 同步最新代码
git checkout develop
git pull origin develop

# 2. 创建功能分支
git checkout -b feature/my-feature

# 3. 编写代码和测试
# ...

# 4. 运行测试
./run_tests.sh

# 5. 提交代码
git add <changed-files>
git commit -m "feat: 简洁描述变更内容"

# 6. 推送到远程
git push origin feature/my-feature

# 7. 创建 Pull Request → develop 分支
```

### 4.3 提交信息规范

采用 [Conventional Commits](https://www.conventionalcommits.org/) 规范：

```
<type>: <简短描述>

<详细说明（可选）>
```

类型包括：

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 Bug |
| `docs` | 文档变更 |
| `refactor` | 重构 |
| `test` | 测试相关 |
| `chore` | 构建/工具链 |
| `style` | 代码格式 |
| `perf` | 性能优化 |

示例：

```
feat(channel): 支持 QQ 频道消息撤回功能

- 实现消息撤回 API 调用
- 添加撤回权限校验
- 更新相关测试
```

## 5. 编码规范

### 5.1 Python 风格

- **格式**: 遵循 [Black](https://github.com/psf/black) 代码格式
- **导入顺序**: 标准库 → 第三方库 → 本地模块（分组排序）
- **类型注解**: 使用 PEP 484 类型注解
- **命名约定**:
  - 类名: `PascalCase`
  - 函数/方法: `snake_case`
  - 常量: `UPPER_SNAKE_CASE`
  - 私有成员: `_leading_underscore`

### 5.2 代码质量检查

项目使用以下工具进行代码质量检查：

```bash
# 类型检查
mypy jiuwenclaw/

# 代码格式检查
black --check jiuwenclaw/

# Linting
ruff check jiuwenclaw/

# 安全扫描
bandit -r jiuwenclaw/
```

### 5.3 文档风格

- 中文文档使用简洁明了的表述
- 代码注释使用中文（面向国内开发者）
- 公共 API 需要有文档字符串
- 新增功能需要同步更新文档

## 6. 测试

### 6.1 运行测试

```bash
# 运行所有测试
./run_tests.sh

# 仅运行单元测试
./run_tests.sh -u

# 带覆盖率报告
./run_tests.sh -c

# 并行运行
./run_tests.sh -p

# 使用 pytest 直接运行
pytest tests/unit_tests/test_config.py -v
```

### 6.2 测试要求

- 新功能必须有对应的单元测试
- Bug 修复需要添加回归测试
- 保持测试覆盖率不降低
- 使用 `pytest` 和 `pytest-asyncio` 编写测试

### 6.3 测试目录结构

```
tests/
├── conftest.py                    # 共享 Fixtures
├── unit_tests/                    # 单元测试
│   ├── test_config.py
│   ├── test_utils.py
│   └── ...
├── system_tests/                  # 集成测试
│   └── ...
└── unit/                          # 频道测试
    ├── channel/
    └── ...
```

## 7. Pull Request 指南

### 7.1 PR 要求

1. **描述清晰** — 说明变更原因、实现方式、测试方法
2. **单一职责** — 一个 PR 只做一件事
3. **测试覆盖** — 包含相关测试
4. **文档同步** — 更新相关文档
5. **无破坏性变更** — 如需破坏性变更，需在 PR 描述中明确标注

### 7.2 PR 模板

```markdown
## 描述

[描述变更内容]

## 类型

- [ ] 新功能 (feat)
- [ ] Bug 修复 (fix)
- [ ] 文档 (docs)
- [ ] 重构 (refactor)
- [ ] 测试 (test)
- [ ] 其他

## 测试

- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] 手动测试验证

## 相关 Issue

Closes #<issue-number>
```

### 7.3 审核流程

1. 提交 PR → 自动触发 CI 检查
2. 项目维护者审核代码
3. 根据反馈修改
4. CI 通过且审核同意后合并

## 8. 新增频道指南

JiuwenClaw 支持多频道架构，新增一个频道通常需要：

1. **在 `jiuwenclaw/channel/` 下创建频道文件**，实现 `BaseChannel` 抽象类：

```python
from jiuwenclaw.channel.base import BaseChannel

class MyChannel(BaseChannel):
    async def start(self):
        # 启动频道连接
        pass

    async def stop(self):
        # 停止频道
        pass

    async def send_message(self, message, session_id):
        # 发送消息到用户
        pass

    async def normalize_message(self, raw):
        # 将平台原始消息转为统一格式
        pass
```

2. **在 `app.py` / `app_gateway.py` 中注册频道**
3. **在 `config.yaml` 中添加频道配置项**
4. **编写使用文档**

## 9. 新增工具指南

Agent 工具位于 `jiuwenclaw/agentserver/tools/`，新增工具步骤：

1. 在工具目录创建工具函数
2. 在 `interface.py` 的 `JiuWenClaw` 类中注册工具
3. 编写对应的单元测试
4. 更新工具文档
