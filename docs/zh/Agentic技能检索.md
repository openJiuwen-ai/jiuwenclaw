# Agentic 技能检索
---

## 概念科普

### Agentic 技能检索是什么

Agentic 技能检索是 JiuwenSwarm 面向**较大规模已安装技能**场景提供的技能目录检索能力。

当已安装技能数量较少时，智能体可以直接查看技能列表并选择合适技能；当技能数量达到几十、上百甚至更多时，直接把所有技能注入上下文会带来两个问题：

| 问题 | 影响 |
|------|------|
| 上下文占用过高 | 用户任务、文件内容和历史对话更容易被挤出上下文 |
| 注意力分散 | 模型容易被大量无关技能干扰，漏掉真正需要的技能 |

Agentic 技能检索通过离线构建一棵**已安装技能树**，并在运行时提供目录浏览工具，让智能体像查目录一样逐层披露相关分支，再决定读取哪些 `SKILL.md`。

### 它解决什么问题

适合以下场景：

- 已安装技能数量较多，不适合把全量技能直接放进 system prompt。
- 用户任务需要组合多个领域能力，例如“读取 PDF → 抽取表格 → 生成报告”。
- 用户没有明确指定技能名称，但任务明显可能受益于已安装技能。
- 团队/集群模式中，Leader 需要先识别相关技能，再组织后续执行。

不适合以下场景：

- 只有很少技能，直接列出技能即可。
- 用户已经明确指定要使用某个技能。
- 当前任务不需要任何已安装技能。
- 需要安装新技能；Agentic 技能检索只检索**已安装技能**，不负责安装。

### 基本工作流

```text
安装技能
  ↓
构建本地技能树索引
  ↓
用户发起任务
  ↓
智能体根据任务选择技能树分支
  ↓
skill_branch_explore 展开相关分支
  ↓
必要时 skill_branch_peek 查看分支摘要
  ↓
发现候选技能
  ↓
读取相关 SKILL.md
  ↓
按 JiuwenSwarm 原有执行能力完成任务
```

Agentic 技能检索只负责“找技能”。它不替代 JiuwenSwarm 原有的执行、文件处理、工具调用、团队派发等能力。

### 三个运行时工具

启用后，智能体会获得以下工具：

| 工具 | 作用 | 使用时机 |
|------|------|----------|
| `skill_branch_explore` | 展开技能树分支，披露下一级分支或候选技能 | 主要检索工具，优先使用 |
| `skill_branch_peek` | 查看分支的轻量摘要和覆盖信息，不展开技能树 | 不确定某个分支是否值得展开时使用 |
| `skill_index_build` | 构建或复用本地技能树索引 | 仅当检索工具提示索引缺失或过期时调用 |

> 一般情况下，模型应先调用 `skill_branch_explore` 或 `skill_branch_peek`。只有工具明确提示“索引未构建或过期”时，才调用 `skill_index_build`。

### 聊天中的可视化

一轮对话中，模型可能多次调用 `skill_branch_explore` 和 `skill_branch_peek`。Web 页面会把这些调用合并展示为一棵动态扩展的技能树：

- `explore`：展开节点的下属分支或技能。
- `peek`：给节点补充分支摘要，不展开树。
- 多次调用会更新同一棵树，而不是堆叠多个孤立工具卡片。
- 当模型发现候选技能后，技能节点会出现在树的末端，便于用户理解模型选择依据。

这使用户能看到智能体如何从第一层分类逐步定位到具体技能。

## 操作指导

### 1. 安装技能

Agentic 技能检索只检索已安装技能。请先在左侧导航栏 **技能** 页面安装需要的技能。

技能安装方式见 [技能系统](技能.md)。

### 2. 开启 Agentic 技能检索

操作路径：

```text
左侧导航栏 → 配置信息 → Agentic技能检索
```

打开 **启用技能检索** 后保存配置。

关闭该开关后，JiuwenSwarm 不会注册技能检索工具，也不会注入技能树提示，系统会回到原有技能使用流程。

### 3. 构建技能索引

操作路径：

```text
左侧导航栏 → 技能 → 技能索引 → 构建索引
```

构建过程会扫描已安装技能，读取技能名称、描述和 `SKILL.md`，并生成本地技能树索引。构建完成后会复用同一套索引，不需要每次启动都重新构建。

当以下情况发生时，建议重新构建：

- 安装、卸载或大量修改了技能。
- 页面提示索引缺失、过期或构建失败。
- 调整了树根分层配置、最大树深等构建参数。

### 4. 使用技能检索

通常不需要用户手动调用工具。正常输入任务即可，例如：

```text
请优先利用当前已安装技能完成该任务；如果发现相关技能，请结合技能内容给出结果。

我有一份 PDF 合同和一份 Excel 表格，请提取关键条款，核对金额字段，并生成一份中文审阅报告。
```

启用 Agentic 技能检索后，模型会先浏览技能树，找到可能相关的 PDF、Excel、文档审阅、报告生成等技能，再决定读取哪些 `SKILL.md`。

### 5. 查看检索过程

在聊天消息中展开技能检索树，可以看到：

- 模型探索了哪些第一层分类。
- 哪些分支被 `peek` 查看过。
- 哪些分支被 `explore` 展开。
- 最终出现了哪些候选技能。

如果某个技能被认为相关，模型后续可能会读取该技能的 `SKILL.md`，再按技能说明执行任务。

## 配置说明

常用配置项位于 **配置信息 → Agentic技能检索**。

| 配置项 | 说明 |
|--------|------|
| 启用技能检索 | 全局开关。关闭后严格走原有技能流程 |
| 树根分层配置 | 第一层分类定义，用于引导技能树构建 |
| 最大树深 | 控制技能树最大分层深度 |
| 拆分阈值基数 | 控制分支过大时触发继续拆分的阈值 |
| 构建并发数 | 构建索引时的并发数量 |
| 构建重试次数 | LLM 分类或分支生成失败时的重试次数 |
| 构建请求超时 | 单次构建请求的超时时间 |
| 构建总超时 | 整体构建过程的最长时间，`0` 表示不限制 |
| 分类批大小上限 | 单次分类时的技能批大小 |
| 启用构建后处理 | 构建后尝试整理过小或不清晰的分支 |
| 启用等价分支合并 | 构建后合并语义重复的分支 |
| 单次披露深度 | `skill_branch_explore` 单次向下披露的层数 |
| 紧凑编码模式 | 是否使用更紧凑的节点编码 |
| 平铺检索树 | 是否将树结构平铺展示 |

默认检索采用非紧凑、非平铺模式，以保留更清晰的树结构和分支语义。

### 树根分层配置

树根分层配置用于定义第一层分类。它可以帮助构建过程把大量技能分发到互斥、清晰、稳定的大类中。

建议分类满足：

- 覆盖常见用户任务。
- 兄弟分类尽量互斥。
- 描述简洁，便于模型判断。
- 不要把某个具体工具、框架或技能名写成根分类，除非这是你们的主要业务边界。

页面会显示默认配置，用户可以直接编辑并保存。

## 常见问题

### 为什么开启后模型没有调用技能检索工具？

可能原因：

- 当前任务已经明确指定了技能。
- 当前任务不需要已安装技能。
- 索引未构建，且模型尚未触发检索工具。
- 全局开关未开启。

可以在任务中明确说明“请优先利用当前已安装技能完成该任务”。

### 为什么工具提示索引未构建？

请进入：

```text
技能 → 技能索引 → 构建索引
```

或让模型在工具提示要求下调用 `skill_index_build`。构建完成后再次发起任务。

### 为什么构建时间较长？

构建会读取所有已安装技能，并调用模型生成分支和分类。技能越多、树越深，耗时越长。构建完成后索引会复用，不需要每轮对话重建。

### 它会自动安装新技能吗？

不会。Agentic 技能检索只检索已安装技能。安装新技能仍需通过 **技能** 页面完成。

### 它会替代集群模式的 Leader 派发吗？

不会。它只帮助 Leader 或普通智能体找到相关技能。具体如何拆解任务、读取技能、执行工具、组织团队，仍由 JiuwenSwarm 原有运行模式完成。
