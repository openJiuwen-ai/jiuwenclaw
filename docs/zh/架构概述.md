# 架构概述

> 本文档描述 JiuwenClaw 的整体系统架构、部署模式、核心组件及其交互关系。

## 1. 系统定位

JiuwenClaw 是一个**自托管的 AI Agent 系统**，充当"智能管家"角色。它将大语言模型（LLM）的能力通过多种即时通讯渠道提供给最终用户，并具备技能进化、定时任务、记忆系统、浏览器自动化、上下文压缩等高级功能。

项目基于华为 `openjiuwen` 框架构建，以 ReAct 模式驱动 Agent 推理与行动。

## 2. 总体架构

JiuwenClaw 采用**分层、模块化、事件驱动**的架构设计，核心分为三层：

```
┌─────────────────────────────────────────────────────┐
│                  用户交互层                           │
│  (Web UI / Feishu / Telegram / DingTalk / 微信等)    │
└──────────────────────┬──────────────────────────────┘
                       │ 多渠道消息
┌──────────────────────▼──────────────────────────────┐
│                  网关层 (Gateway)                     │
│  消息路由 · 频道管理 · 会话管理 · 心跳 · 定时任务     │
│  扩展管理 · E2A 协议适配                             │
└──────────────────────┬──────────────────────────────┘
                       │ E2A 协议 (WebSocket)
┌──────────────────────▼──────────────────────────────┐
│                  Agent 运行时层                       │
│  ReAct Agent · LLM 交互 · 工具系统 · 技能管理         │
│  记忆系统 · 上下文压缩 · 权限检查                     │
└─────────────────────────────────────────────────────┘
```

### 2.1 用户交互层

由多种**通信频道（Channel）**构成，每个频道对接一种即时通讯平台：

| 频道 | 类型 | 说明 |
|------|------|------|
| Web Channel | 浏览器 | 主 Web UI，通过 WebSocket 通信 |
| Feishu | 企业 IM | 飞书/Lark 机器人 |
| DingTalk | 企业 IM | 钉钉机器人 |
| Telegram | 消费 IM | Telegram Bot |
| Discord | 消费 IM | Discord Bot |
| WhatsApp | 消费 IM | WhatsApp Business API |
| WeCom | 企业 IM | 企业微信 |
| WeChat | 消费 IM | 个人微信 |
| QQ | 消费 IM | QQ 机器人 |
| Weibo | 社交媒体 | 微博私信/评论 |
| Xiaoyi | 语音助手 | 华为小艺助手 |

每个频道实现 `BaseChannel` 抽象基类，统一的消息收发接口使得添加新频道非常便捷。

### 2.2 网关层 (Gateway)

网关层是系统的中枢，负责：

- **ChannelManager** — 管理所有频道的生命周期（注册、启动、停止、配置热更新）
- **MessageHandler** — 维护双消息队列，将用户消息路由到 Agent，将 Agent 响应分发回对应频道
- **AgentClient** — 通过 WebSocket 连接 AgentServer，发送 E2A 信封格式的请求
- **HeartbeatService** — 定时心跳，保持 Agent 活跃
- **CronSchedulerService** — 基于 cron 表达式的定时任务调度
- **ExtensionManager** — 扩展/插件系统管理
- **SessionMap** — 会话映射管理

网关层实现了 **E2A（Everything-to-Agent）协议**，将所有外部消息统一封装为标准信封格式，屏蔽底层通信协议差异。

### 2.3 Agent 运行时层 (AgentServer)

Agent 运行时是系统的智能核心，包含：

- **JiuWenClaw (IAgentServer)** — 核心 Agent 类，初始化 ReActAgent 配置，注册所有工具
- **JiuClawReActAgent** — 自定义 ReAct 循环，继承自 `openjiuwen` 的 ReActAgent
- **AgentWebSocketServer** — 内部 WebSocket 服务端，供 Gateway 连接
- **PromptBuilder** — 从 PRINCIPLE/TONE/HEARTBEAT markdown 文件构建系统提示词
- **SkillManager** — 技能的安装、卸载、列表、市场集成（skillnet.ai）
- **SessionHistory** — 对话会话持久化管理
- **Tool System** — 丰富的工具集（浏览器、任务、记忆、MCP、Todo 等）
- **Checkpointer** — 会话检查点/断点续传

## 3. 部署模式

JiuwenClaw 支持两种部署模式：

### 3.1 单体模式（默认）

```
jiuwenclaw-start
     │
     ├── app_web.py (端口 5173)     — 前端静态文件服务 + 反向代理
     └── app.py (端口 19000/18092)  — Gateway + Agent 合并运行
```

推荐个人使用。单个进程同时运行 Gateway 和 Agent，内部通过内存通道通信。

### 3.2 分离部署模式

```
jiuwenclaw-gateway (端口 19000)          jiuwenclaw-agentserver (端口 18092)
     │                                            │
     ├── WebChannel                               ├── JiuWenClaw Agent
     ├── ChannelManager                           ├── AgentWebSocketServer
     ├── MessageHandler                           ├── SkillManager
     ├── HeartbeatService                         ├── SessionHistory
     └── CronSchedulerService                     └── Tool System
              │                                            │
              └────────── WebSocket (E2A 协议) ────────────┘
```

适用于生产环境或分布式部署，Gateway 和 Agent 可运行在不同机器上，通过 WebSocket 通信。

### 3.3 Web 前端服务

```
app_web.py (端口 5173)
  ├── 静态文件服务 — 提供 Vue.js/React 构建的 SPA
  ├── /ws → WebSocket 反向代理到后端 (端口 19000)
  ├── /api → HTTP 反向代理（预留）
  └── /file-api/ → 文件浏览/编辑 API
```

## 4. 数据流

### 4.1 用户消息处理流程

```
用户 → 频道 (Web/Feishu/Telegram 等)
  │
  ▼
Channel.normalize_message()  — 频道特定消息解析
  │
  ▼
MessageHandler._user_messages 队列
  │
  ▼
MessageHandler._consume_messages()  — 内部消费循环
  │
  ▼
AgentServerClient.send_request()  — 包装为 E2AEnvelope
  │
  ▼
WebSocket → AgentServer
  │
  ▼
AgentWebSocketServer.on_message()  — 解析 E2A 信封
  │
  ▼
JiuWenClaw.process_message()
  │  ├── build_system_prompt()   — 构建系统提示词
  │  ├── build_user_prompt()     — 构建用户提示词
  │  ├── Runner.run()            — ReAct 推理循环
  │  │   ├── LLM 调用
  │  │   ├── 工具执行（浏览器/记忆/搜索等）
  │  │   └── 技能调用
  │  └── 结果流式返回
  │
  ▼
WebSocket → Gateway
  │
  ▼
AgentServerClient._process_ws_text()  — 解析 E2AResponse
  │
  ▼
MessageHandler._response_to_message()  — 转为 Message 对象
  │
  ▼
MessageHandler._robot_messages 队列
  │
  ▼
ChannelManager._consume_robot_messages()
  │
  ▼
对应频道 → 用户
```

### 4.2 心跳流程

```
GatewayHeartbeatService (可配置间隔)
  │
  ├── 构建心跳提示词 (来自 HEARTBEAT.md 模板)
  ├── 通过 AgentServerClient 发送给 Agent
  └── Agent 响应可转发到指定频道（如有需要）
```

### 4.3 定时任务流程

```
CronSchedulerService
  │
  ├── 加载 cron_jobs.json 中的任务定义
  ├── 使用 croniter 解析 cron 表达式
  ├── 到期时：
  │   ├── 先发送 wake 消息唤醒 Agent
  │   ├── 发送任务提示词
  │   └── 结果推送到目标频道
  └── 支持通过频道消息 / API 增删改查
```

## 5. E2A 协议（Everything-to-Agent）

E2A 是 JiuwenClaw 内部自定义的通信协议，用于 Gateway 与 AgentServer 之间的消息交换。

### 核心数据结构

```
E2AEnvelope（请求信封）
  ├── version: str          — 协议版本 ("1.0")
  ├── provenance            — 出处信息（源协议、转换器等）
  │   ├── source_protocol   — ACP / A2A / E2A
  │   ├── converter         — 转换器标识
  │   └── converted_at      — 转换时间
  ├── session_id: str       — 会话 ID
  ├── identity              — 身份信息
  │   ├── origin            — USER / SYSTEM / AGENT / SERVICE
  │   └── user_id           
  ├── params                — 请求参数
  │   ├── query             — 用户消息文本
  │   ├── channel           — 来源频道
  │   ├── files/attachments — 文件引用
  │   └── context           — 上下文信息
  └── channel_context       — 频道上下文

E2AResponse（响应）
  ├── kind                  — 响应类型
  ├── session_id
  ├── status                — IN_PROGRESS / COMPLETED / ERROR
  ├── content               — 文本内容（可能为空，如有 parts）
  ├── parts                 — 多部分内容（文本/工具调用/文件等）
  ├── is_complete           — 是否完成
  └── error                 — 错误信息
```

协议同时支持 **ACP** (JSON-RPC 风格 Agent Communication Protocol) 和 **A2A** (Google 式 Agent-to-Agent) 两种外部协议的适配转换。

## 6. 配置系统

配置系统采用**双层结构**：

### 6.1 用户工作区 (`~/.jiuwenclaw/`)

```
~/.jiuwenclaw/
  ├── config/
  │   ├── config.yaml    — 主配置文件（YAML，支持注释保留）
  │   └── .env           — 环境变量（API Key、模型配置等敏感信息）
  ├── agent/
  │   ├── home/          — Agent 工作区
  │   │   ├── PRINCIPLE.md  — Agent 行为原则
  │   │   ├── TONE.md       — Agent 语气风格
  │   │   ├── HEARTBEAT.md  — 心跳提示词模板
  │   │   └── workspace/    — 文件/工作区
  │   ├── sessions/      — 会话历史持久化
  │   └── skills/        — 已安装的技能
  ├── memory/            — 长期记忆（向量数据库）
  └── cron_jobs.json     — 定时任务定义
```

### 6.2 环境变量解析

`config.py` 中的 `resolve_env_vars()` 函数递归解析 YAML 中的 `${VAR:-default}` 语法，将环境变量注入配置值。API Key 和 Token 等敏感字段支持自动解密。

## 7. 工具系统

Agent 注册了丰富的工具集，通过 ReAct 循环按需调用：

| 工具类别 | 工具 | 说明 |
|----------|------|------|
| **浏览器** | browser_mcp_server | 基于 Playwright 的浏览器自动化 |
| **记忆** | memory_search / memory_get / write_memory / edit_memory / read_memory | 长期记忆读写检索 |
| **任务** | task_plan / task_status / task_list / task_cancel | 多步骤任务规划与执行 |
| **MCP** | get_mcp_tools | Model Context Protocol 工具集成 |
| **Todo** | query_todos / add_todo / update_todo / delete_todo | 待办事项管理 |
| **文件** | send_file | 文件发送 |
| **小艺手机** | 30+ 工具 | 定位、笔记、日历、联系人、相册、文件、电话、短信、闹钟等 |

> 注意：部分工具（音频/视频/图像理解）当前被注释禁用，可在 `interface.py` 中启用。

## 8. 技能系统

技能（Skill）是 JiuwenClaw 的扩展能力单元，支持：

- **本地安装** — 从本地目录安装技能
- **市场安装** — 通过 skillnet.ai 平台搜索和下载技能
- **自演进** — Agent 可根据对话自动创建、修改和安装技能
- **Skill Net** — 社区技能市场集成

技能存储在 `~/.jiuwenclaw/agent/skills/` 目录下，通过 `SkillManager` 统一管理生命周期。

## 9. 记忆系统

记忆系统为 Agent 提供长期上下文保持能力：

- **向量存储** — 基于 ChromaDB 或 sqlite-vec
- **主动记忆** — Agent 可主动写入和检索记忆
- **记忆工具** — 搜索、读取、写入、编辑记忆
- **检查点** — 会话断点续传，支持持久化

## 10. 安全机制

- **API Key 加密** — 支持通过 `CryptoProvider` 接口加密存储敏感凭据
- **工具权限检查** — 可选的工具调用权限守卫
- **环境变量隔离** — 敏感信息通过 `.env` 文件管理，不硬编码

## 11. 可观测性

集成 **OpenTelemetry** 实现可观测性：

- 追踪（Tracing）— Agent 调用链路跟踪
- 指标（Metrics）— 系统运行指标
- 日志（Logging）— 按组件分离的轮转日志（gateway.log / channel.log / agent_server.log / full.log）

## 12. 扩展系统

扩展系统允许在不修改核心代码的情况下增强功能：

- **ExtensionManager** — 扩展加载与管理
- **Extension SDK** — `jiuwenclaw/extensions/sdk/` 提供开发工具包
- **回调兼容** — `callback_compat.py` 确保与旧版回调解耦

扩展开发详见[扩展系统文档](扩展系统.md)。
