# 用户可观测日志设计

## 1. 背景与问题

### 1.1 问题描述

在流式响应场景下，JiuwenClaw 的日志系统无法区分用户可见的业务日志和技术内部日志。所有日志混在一起输出，导致以下问题：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         日志噪音分析（流式响应场景）                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  实际运行日志统计（1000 条用户可见日志样本）：                                  │
│  ─────────────────────────────────────────────────────────────────           │
│  • 消息派发日志（重复噪音）:  ~980 条 (98%)                                   │
│  • 关键用户操作日志:      ~20 条 (2%)                                        │
│                                                                             │
│  派发日志示例（噪音）：                                                       │
│  2026-03-27 11:51:27.050 INFO jiuwenclaw.gateway.channel_manager:           │
│  从 robot_messages 取出，准备派发: id=msg123 channel_id=feishu               │
│  2026-03-27 11:51:27.100 INFO jiuwenclaw.gateway.channel_manager:           │
│  已派发到 Channel: channel_id=feishu id=msg123                               │
│  （流式响应时会产生数百条类似的日志）                                          │
│                                                                             │
│  用户真正关心的日志：                                                         │
│  2026-03-27 11:51:26.142 INFO jiuwenclaw.tools.note:                        │
│  [NOTE_TOOL] Creating note - title: 会议记录                                 │
│  2026-03-27 11:51:26.890 INFO jiuwenclaw.tools.note:                        │
│  [NOTE_TOOL] Note created: title=会议记录, id=12345                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 核心痛点

| 痛点 | 描述 |
|------|------|
| 用户体验差 | 流式响应时日志噪音过高，用户难以关注关键操作 |
| 可观测性受限 | 无法向用户展示只与其操作相关的日志 |
| 问题定位难 | 出问题时无法快速判断是用户操作问题还是系统内部问题 |

## 2. 设计目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| 分级展示 | 区分关键操作和进度信息，减少噪音 | 🔴 高 |
| 自动输出 | Tag 自动出现在所有输出位置（控制台、日志文件） | 🔴 高 |
| 零破坏性 | 不影响现有日志系统功能 | 🔴 高 |
| 可观测集成 | 支持按级别过滤展示 | 🟡 中 |
| API 统一 | 只使用字符串值，消除布尔值/字符串混用 | 🟡 中 |

## 3. 分级 Tag 体系

### 3.1 Tag 定义

采用两级 Tag 体系，将用户可见日志分为关键操作和进度信息：

| Tag | user_visible 值 | 用途 | 预计占比 |
|-----|-----------------|------|----------|
| `[USER]` | `'critical'` | 关键用户操作（创建笔记、查询结果、操作成功/失败） | ~2% |
| `[USER_PROGRESS]` | `'progress'` | 进度信息（消息派发、数据流转） | ~98% |
| 无 Tag | 不设置 | 技术内部日志（系统启动、内部循环、技术错误） | - |

### 3.2 Tag 在日志中的位置

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          日志格式示例                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  关键用户操作（[USER] Tag）：                                                 │
│  2026-05-26 11:51:26.142 [123] INFO user_id=u001 domain_id=d001 app_id=a001 │
│  [USER] jiuwenclaw.tools.note:89: [NOTE_TOOL] Creating note                 │
│        │      │      │        │            │                                │
│     进程ID  级别   身份字段    Tag         logger:行号                         │
│                                                                             │
│  进度信息（[USER_PROGRESS] Tag）：                                            │
│  2026-05-26 11:51:27.050 [123] INFO user_id=u001 domain_id=d001 app_id=a001 │
│  [USER_PROGRESS] jiuwenclaw.gateway:42: 从 robot_messages 取出...            │
│                                                                             │
│  技术内部日志（无 Tag）：                                                      │
│  2026-05-26 11:51:25.335 [123] INFO user_id=null domain_id=null app_id=null │
│  jiuwenclaw.gateway.agent_client:15: 正在连接 AgentServer                    │
│                          ↑                                                  │
│                    没有 Tag，直接是 logger 名                                  │
│                                                                             │
│  注：身份字段（user_id/domain_id/app_id）始终输出，便于日志聚合分析            │
│     当身份信息未设置时，输出 null 值                                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 设计原则

1. **API 统一性** — 只使用字符串值 `'critical'` 或 `'progress'`，不再支持布尔值
2. **精确标记** — 只标记用户真正关心的日志，技术日志默认无 Tag
3. **元数据式 Tag** — Tag 位置在日志级别之后、logger 名称之前，不破坏时间戳连续性
4. **业务错误分离** — 只有用户可理解的业务错误才标记，技术性错误不标记

## 4. 技术实现架构

### 4.1 日志处理流程

## 5. API 使用方式

### 5.1 日志记录 API

通过 Python logging 的 `extra` 参数传递标记：

```python
# 关键用户操作（产生 [USER] Tag）
logger.info(
    "创建笔记: %s",
    title,
    extra={'user_visible': 'critical'}
)

# 进度信息（产生 [USER_PROGRESS] Tag）
logger.info(
    "正在发送回复给用户...",
    extra={'user_visible': 'progress'}
)

# 技术内部日志（无 Tag）
logger.info("正在连接 AgentServer")  # 无 extra 参数
```

### 5.2 日志解析 API（供可观测系统使用）

```python
def get_log_visibility(log_line: str) -> str:
    """判断日志行的用户可见性级别。

    返回值:
        - 'critical': 包含 [USER] Tag，表示关键用户操作
        - 'progress': 包含 [USER_PROGRESS] Tag，表示进度信息
        - 'technical': 不包含任何 Tag，表示技术内部日志
    """
    if "[USER_PROGRESS]" in log_line:
        return 'progress'
    elif "[USER]" in log_line:
        return 'critical'
    else:
        return 'technical'
```

### 5.3 JSON 格式输出

当日志格式设置为 `json` 或 `dual` 时，日志会以 JSON 格式输出。JSON 格式包含以下字段：

```json
{
  "timestamp": "2026-05-26 11:51:26.142",
  "process": 123,
  "level": "INFO",
  "user_tag": "[USER] ",
  "user_id": "user_001",
  "domain_id": "domain_001",
  "app_id": "app_001",
  "logger": "jiuwenclaw.tools.note",
  "lineno": 89,
  "message": "[NOTE_TOOL] Creating note - title: 会议记录",
  "component": "agent_server",
  "user_visible": "critical"
}
```

**字段说明**：

| 字段 | 说明 |
|------|------|
| `timestamp` | 时间戳（文本格式 `"2026-05-26 11:51:26.142"` 或 ISO 8601） |
| `process` | 进程 ID |
| `level` | 日志级别 |
| `user_tag` | 用户可见 Tag（仅在有值时输出） |
| `user_id` / `domain_id` / `app_id` | 身份字段（始终输出，null 值便于日志聚合） |
| `logger` | Logger 名称 |
| `lineno` | 源代码行号 |
| `message` | 日志消息 |
| `component` | 组件分类（gateway/channel/agent_server） |
| `user_visible` | 可见性级别（仅 `critical` 或 `progress` 时输出） |

对于不标记的日志，`user_tag` 和 `user_visible` 字段不会出现在 JSON 输出中。

## 6. 配置选项

### 6.1 日志格式配置

系统支持三种日志输出格式：

| 格式 | 控制台输出 | 文件输出 | 适用场景 |
|------|-----------|----------|----------|
| `text` | 文本格式 | `.log` 文件（文本） | 开发环境 |
| `json` | JSON 格式 | `.json` 文件（JSON） | 生产环境 |
| `dual` | 文本格式 | `.log` + `.json` 文件 | 混合环境 |

```yaml
logging:
  format: json  # 默认：text（开发环境）
```

```bash
# 通过环境变量设置
JIUWENCLAW_LOG_FORMAT=json jiuwenclaw-app
```

### 6.2 环境变量配置

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `JIUWENCLAW_LOG_FORMAT` | `text` | 日志输出格式（text/json/dual） |
| `JIUWENCLAW_LOG_USER_VISIBLE` | `true` | 是否启用 `[USER]` Tag |
| `JIUWENCLAW_LOG_USER_PROGRESS_VISIBLE` | `true` | 是否启用 `[USER_PROGRESS]` Tag |

```bash
# 禁用 [USER] Tag（只显示进度信息）
JIUWENCLAW_LOG_USER_VISIBLE=false jiuwenclaw-app

# 禁用 [USER_PROGRESS] Tag（只显示关键操作，推荐用于用户端）
JIUWENCLAW_LOG_USER_PROGRESS_VISIBLE=false jiuwenclaw-app

# 禁用所有用户可见 Tag
JIUWENCLAW_LOG_USER_VISIBLE=false JIUWENCLAW_LOG_USER_PROGRESS_VISIBLE=false jiuwenclaw-app
```

### 6.3 config.yaml 配置

```yaml
logging:
  # 统一输出格式控制
  format: json  # text/json/dual

  # 日志输出开关
  console_enabled: true   # 控制台日志开关
  file_enabled: true      # 文件日志开关

  # JSON 格式详细配置
  json:
    timestamp_format: text        # 时间戳格式：text 或 iso8601
    include_component: true       # 自动添加组件分类字段
    sanitize_sensitive_data: true # 敏感数据脱敏
    exc_info_style: simple        # 异常信息风格：simple 或 full

  # 用户可见性 Tag 配置
  tags:
    user_visible: true           # 启用 [USER] Tag（关键用户操作）
    user_progress_visible: true  # 启用 [USER_PROGRESS] Tag（进度信息）
```

配置优先级：环境变量 > config.yaml > 默认值

## 7. 日志分类标准

### 7.1 关键操作日志（`user_visible='critical'`）

| 类别 | 包含内容 | 示例 |
|------|----------|------|
| 操作进行中 | 用户发起的操作正在执行 | "正在创建笔记..." |
| 操作成功 | 操作成功完成 | "笔记创建成功，id=12345" |
| 操作失败 | 用户可理解的失败原因 | "创建笔记失败：标题过长" |
| 查询结果 | 用户请求的查询结果 | "找到 3 条备忘录" |
| 权限审批 | 权限请求和审批结果 | "工具 xxx 需要授权，请确认" |

### 7.2 进度信息日志（`user_visible='progress'`）

| 类别 | 包含内容 | 示例 |
|------|----------|------|
| 消息派发 | 消息正在派发到渠道 | "正在发送回复给用户..." |
| 数据流转 | 消息在系统内流转 | "从 robot_messages 取出，准备派发" |
| 中间状态 | 处理过程中的中间状态 | "已派发到 Channel: feishu" |

### 7.3 技术内部日志（不添加标记）

| 类别 | 包含内容 | 示例 |
|------|----------|------|
| 系统启动 | 服务启动、连接建立 | "正在连接 AgentServer" |
| 内部循环 | ReAct 迭代、任务循环 | "ReAct iteration 1/10" |
| 技术错误 | 底层技术错误 | "Connection timeout" |
| 调试信息 | 所有 DEBUG 级别日志 | 任何 logger.debug() 调用 |
