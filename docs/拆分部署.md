# 拆分部署（agentserver -> gateway -> web）

JiuwenClaw 支持把后端拆成多个独立进程部署。最常见的拓扑是：

1. `jiuwenclaw-agentserver`：只负责 Agent + `AgentWebSocketServer`
2. `jiuwenclaw-gateway`：负责 Gateway（ChannelManager / MessageHandler 等），并通过 WebSocket 连接 AgentServer
3. `jiuwenclaw-web`（静态文件服务）：给浏览器提供前端，并把 `/ws` 反向代理到 Gateway

适用场景：

- 后端服务需要独立伸缩或跨机器部署
- 前端静态资源与后端解耦

---

## 0. 前置准备

确保已经完成初始化（生成 `~/.jiuwenclaw/config/config.yaml` 与 `~/.jiuwenclaw/config/.env` 等运行时文件）：

```bash
jiuwenclaw-init
```

如果你是源码部署（本仓库运行）且 `jiuwenclaw/web/dist` 不存在，需要先构建前端：

```bash
cd jiuwenclaw/web
npm run build
```

---

## 1. 启动 agentserver（先启动，后面 gateway 会连接它）

默认监听：`ws://127.0.0.1:18092`

```bash
uv run jiuwenclaw-agentserver
```

或

```bash
uv run jiuwenclaw-agentserver --host 127.0.0.1 --port 18092
```

也可以通过环境变量指定：

```bash
export AGENT_SERVER_HOST=127.0.0.1
export AGENT_SERVER_PORT=18092
uv run jiuwenclaw-agentserver
```

---

## 2. 启动 gateway（连接 agentserver，并启动 WebChannel）

默认：

- 连接 AgentServer：`ws://127.0.0.1:18092`
- WebChannel 监听：`127.0.0.1:19000`，WebSocket 路径：`/ws`

```bash
uv run jiuwenclaw-gateway \
  --agent-server-url ws://127.0.0.1:18092 \
  --host 127.0.0.1 \
  --port 19000 \
  --web-path /ws
```

---

## 3. 启动 web（前端静态服务 + /ws 反向代理）

默认前端服务监听：`http://127.0.0.1:5173`

关键点：`--proxy-target` 需要指向 gateway 的 WebChannel 地址（http/https 形式），web 会把它转换/用于 `/ws` 代理。

以下命令假设你在仓库根目录下执行（因此 `--dist jiuwenclaw/web/dist` 是相对路径）。

```bash
uv run python -m jiuwenclaw.app_web \
  --host 127.0.0.1 \
  --port 5173 \
  --dist jiuwenclaw/web/dist \
  --proxy-target http://127.0.0.1:19000
```

浏览器打开：

```text
http://127.0.0.1:5173
```
