## 步骤一：信息整理

**目标**：收集足够的信息用于生成 PPT 内容。

### 1.1 判断信息来源

分析用户请求，按以下优先级确定信息来源：

**A. 用户提供了文档**（本地文件路径、附件、上传的文件等）：

1. 查找已安装的文档解析 skill（名称含 `doc`、`document`、`parse`、`reader` 等）
2. 使用该 skill 解析用户指定的全部文档，提取完整内容
3. 整理提取的关键信息、数据、结构和图表

**B. 用户未提供文档，或 Agent 判断现有信息不足以生成高质量 PPT**：

1. 查找已安装的网络搜索 skill（名称含 `search`、`web`、`browse` 等）
2. 根据用户需求和主题，拟定 3-5 个有针对性的搜索关键词
3. 执行搜索，汇总相关信息
4. 如信息仍不充分，可进行 2-3 轮补充搜索

> 两种来源可以并用：先解析文档，再用网络搜索补充文档中缺少的数据或背景信息。

### 1.2 收集用户上传图片

**目标**：从对话上下文中识别用户上传的图片文件，收集路径和语义描述。

1. 扫描对话上下文中用户发送的图片（通常路径为 `/tmp/xy_channel/` 下的 `.jpg`/`.png` 文件）
2. 对每张图片，记录其**本地路径**和**语义描述**（根据图片内容或用户提及的上下文推断）
3. 最多收集最近 10 张用户图片
4. 将收集结果以列表形式记录，供子流程二使用：
   ```
   用户图片清单：
   1. /tmp/xy_channel/xxx.jpg — 星巴克经典Logo白色哑光杯身
   2. /tmp/xy_channel/yyy.png — 产品发布会现场照片
   ```

> 如果对话上下文中无用户图片，跳过此步骤，不影响后续流程。

### 1.3 信息整合

整理所有收集到的信息，识别：
- 核心主题和关键论点
- 支撑数据、案例、图表
- 逻辑结构和层次关系

**完成汇报**：
```
✅ 信息整理完成，共收集 X 个关键信息点
```

## 步骤二：梳理写作思路

**目标**：基于步骤一收集的信息，提炼出一份**简洁的写作思路**，包含以下要点：

- **主题与核心立意**：PPT 要讲什么、核心观点或目的是什么
- **整体逻辑框架**：高层次的叙述脉络（如：现状 → 问题 → 方案 → 效果），不列具体章节标题
- **确定风格主题**：从下表中选一，给出 key 值并说明理由

  | 主题 | key | 适用场景 |
  |------|-----|---------|
  | 学术 | `CreamInk` | 学术/文献/研究报告 |
  | 商务 | `PlatinumExecutive` | 商务/提案/汇报 |
  | 总结 | `WarmPaper` | 教育/总结/分享/培训 |

- **确定结构类型与目标页数**：

  | 条件 | 结构类型 |
  |------|---------|
  | 内容页 ≤12 | 单层结构（封面 → 目录 → 内容页） |
  | 内容页 >12 | 双层结构（封面 → 目录 → 章节页 → 内容页） |

  硬性约束：单层内容页总数 ≤8；双层章节数 ≤8，每章内容页 ≤8

  页数默认规则（用户未指定时）：
  - 内容较少或主题简单：8～10 页内容页
  - 内容适中（常规汇报/方案）：10～15 页内容页
  - 内容丰富（详细报告/研究）：15～20 页内容页
  - 用户明确指定页数时，以用户要求为准

> 写作思路应简洁（5-8 条），聚焦方向和逻辑，**不列具体页面标题或内容细节**。写作思路中必须包含明确的风格 key、结构类型和目标页数，以便用户一并确认。

### A.1 读取生成指南

使用 Read 工具读取 PptxGenJS (`~/.openclaw/workspace/skills/xiaoyi-ppt/pptxgenjs.md`) 教程：

> 读取后严格遵循其中的 API 用法和常见陷阱（颜色无 `#` 前缀、不复用 option 对象等）。

### A.1.5 图片预处理

如果用户提供了图片文件（照片、截图等需要插入 PPT 的图片），在生成前统一转换格式：

```bash
python3 ~/.openclaw/workspace/skills/xiaoyi-ppt/scripts/normalize_images.py image_path 
```

> iPhone 拍摄的 `.jpg` 实际可能是 MPO（多帧）格式，python-pptx / PptxGenJS 直接嵌入会导致显示异常。此步骤通过 Pillow 统一转为标准 JPEG，成本极低，无需判断格式。

### A.2 生成 PPT

基于步骤二的写作思路，**一步到位**生成完整 `.pptx` 文件：

**结构**：封面 → 目录（页数 ≥8 时加入）→ 内容页 → 结束页。每页聚焦一个要点。

**设计基本要求**：
- 自行选定一组与主题匹配的主色 / 辅色 / 强调色（6 位 hex，无 `#`）
- 封面和结束页用深色背景，内容页用浅色背景
- 每页至少包含一个视觉元素（色块、形状、图标），避免纯文字页
- 相邻页不重复同一版式
- 标题 36-44pt，正文 14-16pt
- **页面类型组成**：图文页（text_image）≥ 内容页 25%；纯数据页（stats + big_number）合计 ≤3 页；禁止连续 2 个 stats/big_number。数据优先用 cards 或 numbered_list 承载

**输出**：
```bash
$PPT_SESSION_DIR/output.pptx
```

### A.3 交付

将文件发送给用户：

```
✅ PPT 已生成完毕
- 主题：{title}
- 页数：{N} 页
- 风格：{style_key}
```

> **简易模式到此结束，不执行 step2_outline.md 和 step3_generate_monitor.md。**

## 附录 B：降级触发条件与流程

> 当深度定制流程（子流程二 → 子流程三）连续失败时，按以下规则自动降级到简易模式。

### 降级触发条件

满足以下任一条件即触发自动降级：

| 条件 | 说明 |
|------|------|
| 云服务 SSE 连续失败 ≥2 次 | `generate_ppt.py` 进程异常退出，日志含 `[ERROR]`，且重试后仍然失败 |
| 云服务超时 ≥2 次 | 轮询达到 80 次仍未收到完成标记，且重试后仍然超时 |
| 大纲文件上传失败 ≥2 次 | `--outline-file` 上传步骤连续失败 |

### 降级流程

1. 向用户汇报：「深度排版服务暂时不可用，正在切换到简易生成模式…」
2. 跳转**附录 A：简易生成流程（自动降级路径）**，从 A.1 开始执行
3. 降级后产出与深度定制一致，均交付 `.pptx` 文件

> **禁止行为**：不得在降级前向用户展示"简易模式"选项入口；降级是自动行为，仅告知用户正在切换生成方式。
