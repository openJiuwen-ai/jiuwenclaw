# 执行前风险评估

## 目标

在给出「能不能执行 / 怎么处置」之前完成一次结构化风险扫描，避免跳过扫描直接放行。

- 有代码、命令或文件时，先调用 `risk_scan`，再按返回的 `decision` 说话。
- 命中 confirm / block 时不得静默当作可执行。

## 工作流

### 1. 判定是否需要扫描

满足任一条件即进入步骤 2：

- 用户消息含代码片段、命令、脚本、错误日志或文件附件
- 任务涉及命令执行、脚本编写、文件写入或删除
- 用户要求评估执行风险

纯概念问答、不涉及执行时，注明「无执行风险扫描项」后直接回答。

### 2. 调用 risk_scan

- 有工作区文件路径时：`risk_scan(path="<工作区内路径>")`
- 有粘贴文本时：`risk_scan(content="<文本>", language="<语言>")`
- `language` 取值：`shell` / `python` / `javascript` / `powershell` / `generic`；不传则按文件后缀识别
- 必须等待并读取返回结构，不可假设结果

`content` 与 `path` 二选一，不要同时传。

### 3. 按决策处置

| decision | 本技能动作 |
| --- | --- |
| `allow` | 可执行；可保留小范围验证建议 |
| `warn` | 可执行，但先逐条说明风险再执行 |
| `confirm` | 暂不执行，说明命中规则与建议，取得确认后再执行 |
| `block` | 不可执行，给出替代方案；用户坚持时说明后果并走确认 |

运行时写删与命令执行由执行护栏自动拦截，本技能不必复述拦截实现。

## 决策规则

- 密钥内容级命中（AWS / GitHub / OpenAI / 私钥块）即使文件在工作区内也要提示，不因路径安全而忽略。
- 第三方来源代码额外标注「来源不可信，建议隔离执行」。
- `success=false` 时说明错误原因，不要假装已扫描通过。

## 输出要求

结论必须包含：决策、风险等级、可执行或不可执行、逐条命中项（`rule_id`、片段、原因、建议）。命中项不得合并或省略。
