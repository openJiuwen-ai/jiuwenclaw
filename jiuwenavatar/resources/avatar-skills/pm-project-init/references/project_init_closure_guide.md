# 项目启动与结项指南

> 本指南为 `pm-project-init` Skill 的项目管理方法论参考。

## 启动模式

### 项目章程要点

项目章程是项目的"宪法"，应包含：

1. **Why**：为什么做这个项目（业务目标）
2. **What**：做什么、不做什么（范围边界）
3. **When**：关键时间节点（里程碑）
4. **Who**：谁来做、谁决策（组织与 RACI）
5. **How much**：需要多少资源（预算与人力）
6. **Risk**：主要风险与应对

### WBS 分解原则

1. **100% 原则**：WBS 应覆盖 100% 的项目范围
2. **可交付**：每个工作包应产出可验证的交付件
3. **可估算**：每个工作包应能估算工时（建议 8-40h）
4. **可分配**：每个工作包应有明确的 Owner
5. **层次适中**：通常 3-4 层，过细增加管理成本

### 里程碑设置

| 里程碑类型 | 典型节点 | 评审方式 |
|------------|----------|----------|
| M0 | 项目启动 / Kickoff | 会议 |
| M1 | 需求冻结 | 需求评审会 |
| M2 | 设计完成 | 设计评审会 |
| M3 | 开发完成 | CI 门禁 |
| M4 | 测试完成 | 测试报告 |
| M5 | 上线 | 上线审批 |

### RACI 矩阵说明

| 角色 | 说明 |
|------|------|
| R（Responsible） | 执行者，负责完成任务 |
| A（Accountable） | 批准者，对结果负责（每项任务只有一个 A） |
| C（Consulted） | 顾问，需征求意见 |
| I（Informed） | 知会，需告知结果 |

## 结项模式

### 结项条件

- [ ] 所有计划交付件已完成
- [ ] 验收测试通过
- [ ] 遗留问题已记录并有 Owner
- [ ] 文档已归档
- [ ] 干系人已知悉

### 经验教训总结维度

1. **项目管理**：计划准确性、风险管理有效性
2. **技术方案**：架构决策、技术选型
3. **团队协作**：沟通效率、跨团队协同
4. **质量保障**：Bug 率、测试有效性
5. **流程改进**：哪些流程可以优化
