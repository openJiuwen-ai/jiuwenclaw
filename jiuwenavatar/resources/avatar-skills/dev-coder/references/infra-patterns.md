# Agent 基础设施实现模式

本文件给出 Shell/IO 类问题的常见实现模式，供 `dev-coder` 在基础设施相关任务中参考。它是经验清单，不替代需求与设计文档。

## 1. subprocess 输出保真

- 避免在超时/取消路径只依赖 `communicate()` 返回值。
- 建议单独 drain stdout/stderr，将字节实时写入自建缓冲区。
- 超时后优先返回“已采集到的真实输出”，不要只返回空错误壳。

## 2. 超大输出策略

- 不建议直接暴力截断最后返回给模型的全部输出。
- 推荐持久化完整日志，并返回预览片段 + 文件路径提示。
- 预览应包含足够上下文，避免只保留头部导致排障信息缺失。

## 3. 双流可读性

- stdout/stderr 默认按时序合并更利于定位因果。
- 若必须分开展示，需说明理由，并保证可回溯到原始顺序。

## 4. 超时后的进程清理

- 超时仅杀父进程通常不够，需检查子进程树是否残留。
- 能按进程组清理时优先按进程组清理，避免孤儿进程泄漏资源。

## 5. 交互命令防挂起

- 自动化执行场景应优先非交互模式（如 `sudo -n`）。
- 对可能等待密码或 stdin 的命令，需给出快速失败策略。

## 6. 与“最小改动”关系

- 最小改动是“在正确抽象层上的最小闭环”，不是“只改入口文件”。
- 若根因在 L2/L3，单改 L0 组装层应视为高风险补丁，并向 Leader 说明。
